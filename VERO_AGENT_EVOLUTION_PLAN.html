全球与中国均不存在「钒冶炼专用软件」品类。钒厂复用钢铁通用 L2/MES 栈，或依赖企业自研。钒冶炼数字化正处于从「零」到「有」的窗口期。
C · 冲突
现有钢铁工业软件按工程师视角设计：操作繁琐、术语门槛高、多系统孤岛、手工录入负担重。合格操作工需五六年培养，老师傅经验随退休流失。
Q · 问题
能否用智能体（Agent）形态重构提钒软件，让一线操作工通过自然语言交互获得工艺推荐、异常预警和决策辅助，大幅降低使用门槛？
A · 答案
VERO 已具备行业唯一的机理引擎+知识包+分角色界面资产。三阶段路径：对话层叠加 → 感知闭环 → 自主辅助，18 个月内完成从「工具」到「伙伴」的进化。

核心结论

1. 市场空白真实存在且被官方证实。国内外均无钒冶炼专用工业软件。国内钒钛产线 2018 年前全流程数字化为零，鞍钢 2024 年仍承认「自动化基础较差」；国外 Largo、Bushveld 等钒企的过程控制选型完全不公开——钒厂软件栈是「不公开宣传的同质化基础设施」。

2. 界面繁琐的根因不是设计水平，而是设计立场。现有系统按「工程师/管理者」视角设计（让操作工选 Pattern 配方、跨屏核对数据、7 步报工），而 ISA-101 高性能 HMI 运动 20 年的量化研究证明：不良 HMI 使操作员响应时间延长 40%、误操作率提高 300%。问题不在屏幕，在「系统回答的是画图工程师的问题，不是操作员的问题」。

3. 对话式交互已被国际巨头验证，且位置明确。Siemens Industrial Copilot（200+ 客户，号称效率提升最高 50%）、ABB Genix Copilot、AVEVA AI Assistant 均在 2024-2026 落地——共同模式是 LLM 坐在 L2/L3 之上做「翻译器+检索器+建议器」，不直接控回路。这与 VERO「只决策不执行」的定位完全一致。

4. VERO 的独特优势在于「机理引擎已产品级」。专家A四大平衡引擎 75/75 黄金回归、三层知识包 CF-001~008 口径全部登记仲裁、v0.8 界面已具备炉次号/枪位推荐/外部接口预留——底盘比所有竞品都扎实。差距在模型层（无 LLM、无 RAG、无自学习闭环），恰好是可用 18 个月追赶的部分。

03界面繁琐、易用性差的根因分析

基于 ISA-101 高性能 HMI 运动 20 年研究 + 国内外公开痛点证据，界面繁琐的根因可归结为五层：

根因一：设计立场错位——为「工程师」而非「操作工」设计
现有系统的信息架构围绕工艺工程师的推理路径（参数→公式→模型→趋势）组织，而非操作工的决策路径（我该做什么→现在做还是等→做完怎么确认）。转炉 L2 让操作工从 5 种流量 Pattern × 5 种枪位 Pattern 中人工选择组合——工艺知识门槛完全转嫁给一线。
证据：湛江转炉 HMI 操作模式（plcjs.com）；宝信 MES 面向「全体系质量业务人员」；ASM 结论「系统回答的是画图工程师的问题，不是操作员的问题」
根因二：视觉噪音淹没关键信号
满屏饱和色+拟物化 3D 设备图+无层次的数据堆砌，使异常工况下真正重要的偏差信号被淹没。ISA-101 量化研究：不良 HMI 使响应时间延长 40%、误操作率提高 300%。颜色被滥用为「设备身份标识」而非「偏差指示器」。
证据：ASM Consortium 异常工况管理研究；ISA-101.01-2015 标准；EEMUA 191 报警基准（稳态 150 条/天 vs 现实 5-20 倍超标）
根因三：多系统孤岛 → 人工跨屏核对
L1/L2/L3/L4 分层架构天然产生数据断点。操作工需在 MES、L2 HMI、Excel、纸质台账之间反复切换，手工抄录、跨屏比对。排产员「灵活切换电脑屏幕的两个系统比对数据」是常态而非例外。
证据：承德钒钛排产员跨屏核对（csteelnews.com）；Kardemir「多系统并存→数据不一致」（Primetals 官方）；社科院工经所「数据孤岛严重、单点应用阶段」
根因四：手工录入负担重 → 数据质量恶性循环
专家A钒钛「每天化检验数据上百个」靠人工跑腿送样；报工需 7 步点击导致「先纸质记录、下班补录」；钒钛产线「数据自动采集度不高」。录入负担 → 数据延迟/缺失 → 模型不准 → 操作工不信任系统 → 更依赖手工经验 → 恶性循环。
证据：专家A钒钛远程检化验系统改造前（gtjia.com）；星云智联钒钛产线五大问题（csteelnews.cn）；MES 报工 7 步点击（toutiao.com）
根因五：报警「被积累」而非「被设计」
报警是多年间由「当班的人」逐条添加的，不是被系统设计的。多数存量工厂首次自测即发现超出 EEMUA 191 基准 5-20 倍；大扰动时 10 分钟内超过 300 条，操作员只能机械确认甚至放弃确认。报警洪水 → 告警疲劳 → 真正关键的异常被忽略。
证据：EEMUA 191 基准（hmilibrary.com）；ISA-18.2 报警管理标准；ASM「异常工况中操作员响应延迟是工业事故的首要贡献因素之一」
根因六（深层）：经验不可复制 → 系统只服务老师傅
「合格高炉操作员要培养五六年」（南钢官方）；承德钒钛需「把老一辈炉前技师数十年实操体感转化为标准化算法」。界面设计的隐含假设是「用户已经懂工艺」，导致新手无法独立操作系统——系统没有承载知识，知识只在老师傅脑子里。
证据：南钢×华为立项痛点（news.cn）；承德钒钛「人工经验操作带来的一系列问题」（worldmetals.com.cn）；ABB Genix「捕捉操作员知识」设计目标
根因总结：界面繁琐不是「设计得不好」，而是「设计给了错误的人」。系统围绕工程师的建模思维组织，而一线操作工需要的是「告诉我现在该做什么」。这五层根因环环相扣——立场错位导致视觉噪音，孤岛导致手工录入，手工录入导致数据差，数据差导致报警泛滥，报警泛滥+经验不可复制导致系统只服务老师傅。解药不是更好的屏幕，而是换掉交互范式。

04智能体（Agent）化改造方案

4.1目标形态定义

VERO Agent 不是什么 / 是什么

不是是
不是另一个 HMI/SCADA 画面是坐在现有系统之上的认知层——把数据翻译为行动建议
不是直接控制回路的自动驾驶是决策辅助——推荐、解释、预警，最终动作由人确认
不是通用聊天机器人是领域专家——锚定提钒知识包、操作规程、历史炉次的 RAG
不是替代操作工是放大操作工——让新手拥有老师傅的判断力
不是推倒重来是渐进叠加——在现有引擎/知识包/界面上生长

4.2核心能力地图（六大能力）

① 自然语言交互（NLP Interface）
操作工用自然语言提问/下指令：「这炉 Si 0.26，怎么吹？」→ Agent 调用机理引擎计算并返回行动建议。语音输入+文字输出（车间噪音环境），支持方言识别。对标：Siemens Copilot for Operations（报错翻译→处置建议）、ABB Genix APM Copilot（自然语言查工况）。
② 工艺参数智能推荐（Recommendation Engine）
已有：配吃量+品位预测+枪位推荐（v0.8）。扩展：氧量/供氧时间/冷却剂配比/终点温度的全参数推荐链，每次推荐附带「为什么」（知识包溯源+相似炉次判例+置信度）。推荐逻辑=机理引擎（确定性）+ 历史数据回归（统计修正），不依赖 LLM 幻觉。
③ 异常预警与根因分析（Anomaly Detection & RCA）
已有：黄灯态（Si>0.25/V<0.27）。扩展：多维度异常检测（温度偏差/氧量异常/渣量波动/品位偏离），按 ISA-18.2 设计报警合理化——每条报警必须回答「操作员该做什么、时限多少」。根因分析锚定知识包 CF 冲突登记与历史判例。对标：ABB Genix「哪条线最接近突破限值」。
④ 自主决策辅助（Decision Support）
在人工确认前提下执行复合决策：「本炉例外，按高硅预案走」→ Agent 自动完成：切换枪位模式 + 调整配吃 + 记录留痕 + 通知工艺台。每一步可解释、可回溯、可撤销。红线：不直接下发设定值到 PLC，动作须经人确认并落审计日志。
⑤ 知识固化与传承（Knowledge Capture）
老师傅经验（看火焰、看渣、看料）通过语音随手记录 → 结构化 → 可检索的通道沉淀到知识包。交接班时 Agent 自动生成班报摘要（本班炉次/异常/处置/待跟进）。对标：Siemens Erlangen「交接班效率提升」、ABB Genix「捕捉操作员知识」。
⑥ 持续学习与漂移检测（Learning Loop）
每炉实绩回流：预测品位 vs 实际品位 → 误差 → RLS/梯度下降修正。漂移检测：连续 N 炉 pred_err 超 3σ → 触发口径复审。这是 P3 学习闭环的核心，也是 VERO 从「静态专家系统」进化为「活智能体」的关键。

4.3对话式交互替代传统操作的设计

核心原则：不是用对话框替换所有界面，而是用对话替代「找功能、填表单、翻菜单」的高摩擦操作，保留仪表盘用于「持续监控」的低摩擦场景。

传统操作（高摩擦）对话式替代（低摩擦）底层调用降门槛效果
在 HMI 上从 5×5 Pattern 矩阵中选择枪位/流量配方「这炉 Si 0.26，枪位怎么走？」→「高硅全程 900mm，已标记例外」lance_profile.py + 知识包消除工艺知识门槛
跨 3 个系统查上炉实绩 + 手工计算配吃量「上炉精渣多少？这炉该配多少球团？」→「上炉 14.59%，本炉建议 3.53t」runModel + 相似炉次判例消除跨屏核对
在 MES 中 7 步点击完成报工「确认照单执行」→ 一键/语音确认，自动留痕confirmBtn + registerHeat7 步→1 步
翻阅操作规程 PDF 找高硅预案「Si 超了怎么办？」→「按高硅预案：全程低枪位，已为你标记例外流程」RAG 锚定操作规程消除文档检索负担
交接班时口头/纸质交接，信息丢失「生成本班摘要」→ 自动汇总炉次/异常/处置/待跟进opLog + LLM 摘要交接零遗漏
异常时满屏报警，不知先处理哪个「现在什么情况？」→「品位预测 13.2% 破限，原因是 Si 0.28% 超标，建议…」异常检测 + 根因分析报警→行动指南

4.5分阶段实施路径（18 个月）

P1对话层叠加（0–6 个月）——「能听懂」
目标：在现有 v0.8 界面上叠加对话入口，不动引擎和知识包
技术方案：接入 DeepSeek API（已在 mcp.json 配置）作为 NLU/NLG 层；前端加对话面板（chat widget）；意图识别路由到已有函数（readInput/runModel/lanceProfile/pushLog）；RAG 锚定知识包 YAML + 操作规程 PDF（向量检索）。
交付物：①对话式开吹条件录入（「Si 0.215, V 0.284, 80 吨, 1300 度」→ 自动填充）②对话式配吃/枪位查询（「怎么吹？」→ 调引擎返回建议）③对话式确认留痕（「确认」→ 一键执行）④交接班摘要自动生成
验收标准：炉长用对话完成一炉完整操作（录入→查询→确认），步骤数 ≤传统操作的 50%；意图识别准确率 ≥90%（20 条预定义意图）
P2感知闭环（6–12 个月）——「能看懂」
目标：接入外部数据源（VERO_API 已预留），实现异常预警与根因分析
技术方案：①MES/L2/化验室数据经 VERO_API.applyHeat 自动推送（替代手动录入）②多维度异常检测（温度/氧量/渣量/品位偏差）③报警合理化（按 ISA-18.2 设计，每条报警附「做什么+时限」）④根因分析 RAG（锚定 CF 冲突登记+历史判例+操作规程）⑤炉后台账批量导入（判例库扩充至全量炉次）
交付物：①外部数据自动录入链路（数据源徽标自动切换）②黄灯态升级为多维度预警（含根因+建议动作）③报警自查仪表盘（150 条/天基准自检）④判例库扩充至 100+ 炉次
验收标准：数据自动采集率 ≥80%；报警量降至基准 2 倍以内；异常响应时间（从发生到操作工收到建议）≤30 秒
P3自主辅助（12–18 个月）——「能帮忙」
目标：自学习闭环 + 复合决策辅助，从「被动回答」到「主动建议」
技术方案：①RLS/梯度下降误差回流（每炉实绩 vs 预测 → 自动修正）②漂移检测（连续 N 炉 pred_err 超 3σ → 触发口径复审）③复合决策（「按高硅预案走」→ 自动完成多步操作）④知识固化（语音随手记录 → 结构化 → 可检索）⑤工艺台 Agent 化（仲裁建议自动生成+证据链）
交付物：①自学习闭环上线（模型参数自动标定）②漂移预警（口径复审触发器）③复合决策辅助（一键执行多步预案）④经验库（≥50 条结构化经验）
验收标准：品位预测 RMSE 较 P1 基线降低 ≥15%；例外率（黄灯触发频次）环比下降；新手操作工独立完成整炉操作（无需老师傅指导）

架构核心原则：LLM 坐在引擎之上做「翻译器+检索器+建议器」，引擎做确定性计算，知识包做口径锚定。LLM 不做数值计算（防幻觉），所有推荐值由机理引擎产出、LLM 只做自然语言包装。这与 Siemens/ABB/AVEVA 的工业 Copilot 架构完全一致，且与 VERO「只决策不执行」的红线天然兼容。

4.7风险与红线

风险等级缓解措施
LLM 幻觉导致错误推荐高所有数值由机理引擎产出，LLM 只做包装；推荐值附带置信度+溯源；关键推荐需人工确认
对话误解意图 → 错误操作高意图识别限 20 条预定义意图（非开放式）；关键操作（确认/例外）需二次确认；审计日志全量留痕
OT/IT 边界安全中按 IEC 62443 分区；DMZ 隔离；外部数据只进不出；DeepSeek API 走代理不暴露内网
操作工抵触「被 AI 替代」中定位为「放大操作工」而非替代；保留仪表盘作为后备；知识固化让老师傅经验被尊重而非被取代
数据质量不足 → 自学习退化中P2 先做数据采集率 ≥80% 再上 P3 自学习；漂移检测 3σ 门限防止错误数据污染模型
数据主权（化验/工艺机密）中LLM 调用脱敏（不传原始化验值，只传分档标签）；或参照 Siemens Erlangen 模式全本地边缘部署
