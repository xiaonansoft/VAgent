VERO 界面设计评审报告 v1

针对 VERO_MVP_v0.4.html · 三路专家智能体并行评估（产品+AI 总监 / 工艺专家 / 炉长+操作工）综合
评审对象 v0.4 三维度：信息层级 · 交互流程 · 可视化布局 五角色：产品总监 · AI 总监 · 工艺专家 · 炉长 · 操作工

摘要 · 三条裁决

① 炉长视图信息过载：02 卡 6 个 KPI 有 4 个是工艺校核项（富余/渣量/半钢/物料差），炉长决策不看；「口径选择 2777/15000」是未终审的专家级争议（CF-001），泄漏到生产视线。10 秒读配吃目标守不稳。

② 相似判例（07）位置错位：炉长视图的 2 条判例表信息密度过高，对炉长是干扰而非辅助；工艺工作台的全量判例被压在右栏最底（05/06 之下），对工艺专家却被严重低估——它本该是仲裁的"先例佐证"。

③ 留痕可审计性为零：操作留痕只存内存数组（刷新即失、无哈希、无用户、无炉次键），AI 总监视角下等于无留痕。这是工业级产品的硬伤。

下文按子任务展开：① 相似判例位置分析 ② 五角色功能优先级矩阵 ③ 逐界面三维度评审 ④ 优化路线图。

1.2 合理性评估（三视角共识）

视角判例对该角色的价值当前位置合理性
炉长低。10 秒决策窗口内无暇比对 5 列数据；判例应是"信任锚点"而非"对照表"不合理 放在 02 下方抢视线，与"读配吃"目标冲突

1.3 位置调整建议

炉长视图：移出 07 判例表。改为 02 一句话信任锚——「近 3 炉相似工况实绩 13.6–14.2%，本炉预测 13.30%」嵌在配吃建议下方一行。仅在黄灯态弹 1 条最近炉次（"上炉 Si 0.26 类似，实绩 13.59%，照此执行"）。

工艺工作台：07 升格，与 05 仲裁并排（左 05 决策 / 右 07 判例佐证），构成"裁决—先例"联动；点击判例行联动 06 回放高亮对应炉次。

数据治理台：不单列判例面板（保持角色边界），但在"知识包溯源"里加一行判例库条目数与最近入库时间。

3逐界面三维度评审

3.1 炉长驾驶舱

维度现状问题优化方案
信息层级 02 卡 6 KPI 平铺；口径选择（2777/15000）单选框在 01；无炉次号/班次/时间戳 4 个工艺校核 KPI（富余/渣量/半钢/物料差）对炉长无决策价值却占视线；口径选择是未终审争议泄漏到生产视线；无炉次锚定则留痕无法定位 02 砍到「配吃量+品位」2 大数字 + 灯 + 一句话 + 信任锚（近 3 炉实绩区间）；4 校核 KPI 下沉工艺工作台；口径选择移出（默认 2777，标注"工艺侧已仲裁"）；顶栏加「炉次 #1234 · 3 号炉 · A 班」标识条
交互流程 01 滑杆在左→02 灯在中→确认按钮在 02 底部；黄灯态提示"高硅预案"但无入口 操作工填完滑杆需跨栏找按钮，动线偏；黄灯提到预案却要切到工艺工作台翻找 确认按钮上移贴近 02 大数字；加键盘 Enter 确认；黄灯一句话旁加「查看高硅预案」按钮，一键展开预案要点（不跳转）
可视化布局 grid-top 三栏（330/1fr/400）；LED 灯仅在炉长视图；KPI 大数字 34px 三栏在 1140px 以下折叠为单列，炉长视图变很长；LED 未扩展到其他视图一致性弱 保留三栏；中屏（900-1140）改为「输入列 + 主结果列」两栏，引导卡折叠进顶栏抽屉；LED 状态点扩展到所有视图顶栏

3.2 工艺工作台

维度现状问题优化方案
信息层级 左栏 03+04（轻）；右栏 05+06+07（重，纵向高度远超左） 视觉重心右倾；专家进工作台第一眼应是「裁决—证据」对子，却先看到偏调试的 03 敏感性；07 判例被压在底 左栏置 05 仲裁 + 07 判例（裁决—先例联动并排）；右栏置 06 回放 + 03 敏感性；04 解释卡横跨全宽置顶或底
交互流程 05 仲裁 4 按钮点击仅写一行留痕；06 回放无炉次钻取 决策链太短（无高亮选中行/无理由输入/无联动 06 切口径）；专家怀疑某炉离群无法钻取 点击仲裁按钮→高亮表格对应列 + 弹理由输入框（可选）+ 联动 06 重绘为所选口径预测线；06 回放点炉次点→钻取该炉 Si/V/配吃/品位明细，与 07 判例互为入口
可视化布局 grid2 两栏均分；SVG 图表 viewBox 响应 两栏均分导致右栏三块纵向过长；05 仲裁表与 07 判例表都是表格，并排时列宽不一致难对照 采用「左 1fr / 右 1fr」但左栏固定 05+07 双表并排子布局（内部 grid2）；表头对齐统一 Si/V/品位列宽；06/03 图表共用一条时间轴

3.3 数据治理台

维度现状问题优化方案
信息层级 左 A 黄金回归 + 知识包溯源；右 B 留痕 + P3 接口 黄金回归仅 11 项（Python 75/75），覆盖窄；操作留痕区与计算留痕区并列但前者空时占位尴尬；P3 接口仅占位文字 黄金回归扩到全 75 项（折叠展示，超差项自动展开）；操作留痕区与计算留痕区合并为「会话留痕」带筛选；P3 接口补字段表（即使标注待建，也要列出字段/频率/边界）
交互流程 重新自检按钮；留痕仅内存 操作留痕刷新即失、无哈希、无用户、无炉次键——可审计性为零；JSONL 导出仍是 P2 承诺 留痕落地 localStorage + 时间戳 + 用户 + 炉次键 + 输入快照 + 哈希链；加「导出 JSONL」按钮（P2 升级前置）；自检失败项点击钻取引擎某步
可视化布局 grid2 两栏；gold 表格 min-width 420 横滚 留痕区是 explain 文本框，结构化差；知识包溯源是虚线占位卡，信息密度低 留痕区改结构化表格（时间/用户/炉次/动作/输入快照/哈希）；知识包溯源卡补「31 类参数 × scope × status」迷你表 + 签字状态徽章

3.4 全局元素（顶栏 / 标签页 / 演示模式 / footer）

维度现状问题优化方案
顶栏渐变 + 状态点 + 演示/重置按钮 + 三标签页演示模式只扫 Si/V，不覆盖工艺仲裁与黄金自检；状态点仅"离线运行"无炉次锚定演示剧本扩展为三段（炉长读配吃→工艺仲裁→数据自检）；顶栏加炉次锚定条
标签页三角色 on 态白底高亮角色边界靠标签页，但炉长视图泄漏口径选择，边界未严格标签页加角色图标；炉长视图严格只放 P0 项，专家级内容一律不渲染
footer术语表 + 版本说明信息被动，无导航价值加「快速跳转」锚点（到各视图各面板）+ 版本变更日志链接
