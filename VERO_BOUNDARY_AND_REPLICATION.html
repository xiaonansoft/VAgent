VERO 产品边界与跨厂复制方案 v0.1

提钒冶炼智能体 · 七角色两轮评审收敛 · 2026-09-28 · 所有数字均经实跑核查
一句话结论：VERO 要从「引擎内嵌常数的单点系统」重构为「通用引擎（可公开）+ 客户私有参数包（不出厂）」，中间用 CI 强制边界。这不是整洁问题——当前连常数的一半都核对不到，复制到新厂只能靠人肉比对，成本不降反升。

不做（5 条）——每条都有归属，不是纪律

不做理由说明
直写 PLC责任误动/拒动造成人身设备事故，供应商最多赔合同额；急停是 SIL 硬件回路，非 SIL 软件只能做旁路建议
事中控制定位属 P3；且吹炼 8~12min 不可逆，氧吹了冷料加了撤不回

共享厂级经验IP厂级常数与诀窍不得跨厂流转

边界必须由技术强制，不能只靠文档

  • AST 门禁：断言 ProductionControlWriter 四个方法体仅含 raise；backend 全量禁 import opcua / pymodbus / snap7
  • 路由扫描：枚举 main.py 的 app.routes，断言无写控制端点，只留 resources/read
  • 契约锁死：测试断言建议包 requires_human_confirm=True 且 control_write=="forbidden"
  • 数据不出厂：断言厂级包缺失时走降级而非崩溃

二、复制方案

SKU 与计价

卖「机理引擎 + 厂级配置服务」——软件和知识单卖都不闭环。

构成说明
许可按站点 / 炉座，与交付人日脱钩
实施三档：标准接入 22~27 人日/厂（理想态 10~12，不作为报价基线）/ 深度适配（按点表条目计价 + 工时上限，超量走变更单）/ 联合迭代（含该厂参数反演）
年维保知识包版本与回归门禁
关键：一次性平台投入 40 人日 列产品投入，不进二厂报价——否则第二厂为平台买单，定价说不通。

一次性平台投入合计 40 人日。蓝图 = 平台 40 + 每厂 22~27。

每厂人日已上调（原 10~12 → 现 22~27，其中「标定 + 影子期」12~15），三条理由：
① 铁水温度软测量在接真数据前是空头承诺——温度是主驱动量，冷启动前只能靠化验单/上一炉估计，必然出现「估计值进模型」的降级运行期；原 8~10 人日的前提是「接上真数据后再标定」，但 P0 适配层 12 人日必须先行，时间上不成立。
② 铁水化验单（C/Si/V/Ti）须等班组按炉送样，排班配合是强耦合项。
③ 冷启动需每台班 1 人 × 2 周盯现场 + 每日对齐会。
理想态（P0/P2 就绪、点表标准化、化验排班配合）仍可回到 10~12。最大杠杆仍是 P4 知识包 schema + 参数模板。

GATE-2：交付物内不得携带任何厂的生产实绩

已核实的扩散面——不是改一个 py，是四类载体：
① v_heat_calibration.py:20-37 内联 16 炉逐日实绩（铁水 Si/V + 粗/精渣 V₂O₅）；
② 8 个 HTML 演示页各命中 4 处（VERO_MVP.html + v0.3 / v0.5 / v0.6 / v0.7 / v0.8 / v0.9 / v0.8_bridged，实测含 {day:1,si:.19} 及 13.06~13.59 品位序列）——这些正是给第二厂看的物料，风险高于后端脚本；
③ docs/DATA_INTERFACE_SPEC.md:207 记录「MVP 内嵌 HEATS」；
④ arbitration_demo.py:172 会自动再生 backend/ARBITRATION_DEMO.md——属可再生暴露源，必须连生成逻辑一起改，否则清完下次跑又落地一份。
链路：arbitration_demo.py:22 from ... import HEATS → 实绩会随复制包进入第二厂。

改造方案：

  • HEATS 外置为按 plant_id 取数的私有数据源，代码与 HTML 均不再内联任何真实样例
  • arbitration_demo 与反演器改为接受 heats 入参，不再 import 具体数据集；其报告生成逻辑同步去实绩
  • 8 个 HTML 不必逐个脱敏——只保留一个合成数据版本作为当前演示基线，其余 7 份归档（不重复维护 8 份）
  • 验收项（可勾选，建议入 CI）：全仓（含 HTML/JS 内联、示例数据、截图、生成报告、文档）grep 不到真实炉次数值

证据批次（清点时按此逐项核）：

  • 批次1·后端脚本：v_heat_calibration.py:18 自注「源: Excel 工作表『钒渣钒品位情况』B3:Q6」+ 20-37 行 16 天实绩；arbitration_demo.py:22 引用它，:172 可再生报告
  • 批次2·HTML 内联：8 个演示页均含真实炉次，特征值含粗渣 14.47 / 14.06 / 15.11、精渣 13.25、铁水 V 0.319 / 0.333
残余风险（CI 守不住的部分）：数值匹配只能覆盖明文，守不住换算值、截图、带日期的曲线、流程条上的数字、报告片段。这些必须按仓逐仓处理，且接新厂前逐仓拉网一次，不能只依赖 CI 通过就认定干净。
降级路径须输出显式降级：厂级参数缺失或降级时，输出必须显式标注已降级，且禁止用于 KPI 合同轨——降级值进合同等于拿默认值冒充标定值。

执行顺序：先证据保全（快照 / commit / fork / 下载量留证），再改内容；「下架/转私有」优先于「重写历史」——force push 对已存在的 fork / 镜像 / 缓存无效，「以为删干净了」比「知道没删」更危险。对外通知与补救顺序交法务，不擅自发函。

人日归属决策：GATE-2 从初估 2 人日扩到四类载体 + CI 后重估为 5 人日，计入一次性平台投入（合计 40 人日），不进二厂报价。理由：这是产品合规基线，不是任一厂的定制需求；若为修复历史遗留而向第二厂收费，与「平台投入不进厂报价」原则相悖。

参数包导出边界（可直接对外讲的商业条款）

合同须定义死「参数包导出形态」：
导出 = 该厂参数 + 标定结果 + 证据链（客户数据及其加工物）；
不导出 = 通用引擎、求解器、代码、跨厂方法学改进——我方对脱敏后的通用改进保留所有权。

一句话定位：客户带走自己的知识，我们带走行业能力。 它把「跨厂复制」与「卖数据」彻底分开，是逐厂谈判时最有力的一句。

标准 / 可配置 / 定制三分

类别内容
标准引擎、schema、resolve 合并、证据链、黄金回归、只读边界
可配置B 类真厂级参数（见 §三）、原料与冷料、目标阈值、字段映射与权限
定制新炉型 / 物料机理、非标点表与报表
不进包也不报价A 类化学计量常数（FE_IN_FEO、FE_IN_FE2O3、V2O5_PER_V、MW）——任何厂相同，进包只会制造伪厂差异

客户必交清单（缺一项即无输出）

  1. 现行《提钒操作规程》：冷却剂按 Si 分档查表 kg/t、温度修正 kg/t/℃、冷料上限 t
  2. 冷料实物化验单（Fe₂O₃ / SiO₂ / V₂O₅）
  3. 铁水 C/Si/V/Ti/P/S/Mn 化验口径与送样时延
  4. 半钢终点目标（温度 / 残钒上限 / 保碳下限）
  5. ≥20 炉历史台账（入炉条件 + 实际终点温度 + 渣样全成分）——没有就无法出 KPI，直接卡验收
  6. OPC/Kafka 点表与只读采集授权

3.4 合规：Clean-room 形态

  • 只交付通用引擎；参数由客户自带并标定，存本地或租户密钥库
  • 不进代码、默认值、测试、日志
  • 使用 A/B 衍生成果前须签授权范围与来源声明
紧急项 A（最严重）：backend/app/tools/v_heat_calibration.py:18-37 硬编码了专家A 16 天逐日真实生产实绩（铁水 Si%、铁水 V%、粗钒渣装车样 V₂O₅%、精钒渣 V₂O₅%），且注释直接给出源表定位「Excel 工作表『钒渣钒品位情况』B3:Q6」。
这比常数更严重：常数尚可争辩为经验值，逐日实绩是明文生产记录，且注释指明了源表位置。合规判断：须立即下架/私有化 + 清历史 + 查 fork；仅删除文件不够（历史提交、fork、制品中仍在）。
紧急项 B：33 个专家常数仍在 public 仓库且带 Excel 单元格溯源（!D25 !E15 !E18 等）。同样需私有化 + 清历史。
数据索取口径（对外）：向客户索取冷料分品种加入量时，只索实绩值或其热容当量折算值，不索取配方——冷料配比可能承载客户诀窍。EXPERIENCE_CAPTURE.md §7 的三级 scope 只是内部 SOP，不足以对外构成「默认不共享」承诺，须合同 + 技术隔离 + 审计三者齐备。

最大单点依赖（已按实测修正）：客户台账须逐炉给铁水 C、铁水温度、分品种实际冷料加入量(kg)、粗渣与精渣 V₂O₅、终点温度。
· 最低 n=20 炉可启动标定（出偏差带与基线）；
· n≥30 且铁水 V 极差 ≥0.20pp 才走 CF-001 的统计判别路径——稳态生产天然窄（现有样本实测极差仅 0.049pp），此前「极差 ≥0.30pp」属过度设卡，不作为启动条件；不满足则走 CC-1 出口乙。

转正门槛必须分档，否则是不可达承诺

已实测：即便把已知偏移去掉，残差仍达粗渣 ≈0.83~0.91pp、精渣 ≈1.27~1.36pp（模型欠定，非标定问题）。「≤0.5pp 转正」即使 CF-001 终审也兑现不了，写进合同就是不可达承诺。
分档：默认档＝去偏后 粗渣 ≤0.9pp / 精渣 ≤1.3pp（当前反演已可实现）；≤0.5pp 列为进阶档，须待 CF-001 终审并补齐铁水 C/温度/分品种冷料量等自由度后方可承诺。
且必须锁定对照对象：默认绑粗渣装车样（RMSE ≈1.0pp），精渣仅参考不进判据——两者口径不同，混用会让判据本身不可复现。

P2（回放 + 影子 + 评测集）应升为与 P4 并列的二厂前置 GATE，而非缓释措施：R1（实时数据零接入 + 系统性偏高）在接真数据时即刻暴露，没有 P2 就没有影子期与基线，验收无从谈起。

七、对外声明口径与法务待确认

对外只声明三件事，不承诺「已无泄露」：
① 产品已去生产实绩依赖；② 交付前执行全仓扫描；③ 扫描纳入 CI 校验。
禁止对外声称「已彻底清除」——公网副本（fork、镜像、缓存、制品）不可控，此类承诺无法举证，反而构成新的不实陈述。

客户侧配套：客户清单第 6 条（数据与授权）须升级为合同条款——客户自有数据本地化、不回流、不跨厂使用，写入合同或 DPA，作为与 GATE-2 对等的对外承诺。
