01侦察一：成熟 Skills 生态地图

开源 Agent Skills 生态（skills.sh，兼容 OpenCode/Claude Code/Cursor）已经沉淀了可复用的工作方法论技能，不是代码库，而是"流程知识包"——和我们给冶金专家建知识包是同一个思想，讽刺而正确。

侦察结论

①不需要发明开发流程——brainstorming → plan → spec → TDD → verification 是社区已验证的标准链路，且我们前两轮研讨恰好走完了 brainstorming 阶段；②工业场景特殊性不在流程，在评测数据（黄金数据集）与治理门禁（shadow/仲裁）——这两块生态里没有现成 skill，是我们的自建机会；③安装命令 npx skills add obra/superpowers@writing-plans -g -y（需 Node≥18，本机暂无 Node，装 Node 后一次性配置）。

03侦察三：LLM 应用特有的质量工程流程（工业场景加强版）

黄金数据集（Golden Dataset）——行业的"标准样"

企业级共识流程（Langfuse/Statsig/Arthur AI 2025-2026 文档）：①从真实失败案例取样 → ②标注期望输出 → ③版本化 → ④每次变更跑回归 → ⑤持续补充边界案例。

映射到我们：已有绝佳起点——Excel 75 条黄金值就是机理引擎的 golden dataset（本仓库已建成并 75/75 通过）。要补的是对话侧黄金集：30 条"操作工真实问法→期望回答要点+引用规则"样例，作为归因 Agent 的验收基准。

eléctr护栏：黄金集分三级 L1 机理数字（全自动断言）/ L2 规则引用（半自动）/ L3 解释话术（专家抽评）。

评测门 + Shadow 发布（生产前必经）

LayerLens 五阶段生产框架：预发布门禁 → Shadow 部署 → 持续评测 → 漂移检测 → 回归门禁。与我们的设计完全同构，可直接引用其门禁语义：

· 红线门（何稳）：LLM 输出不含数字设定的静态检查，进 CI；
· 守恒门（高工）：物料/热/钒三关，任何引擎改动必跑；
· 炉次回放门（赵数）：≥300 炉回放，RMSE 劣化>5% 即禁发布；
· shadow 门（沈工）：新规则/新模型按"50 炉并行对照"协议。

06职责分工（RACI 精简版）

四席拍板

角色拍板事项
产品总监MVP 范围冻结、PRD 签认、演示脚本、验收标准
技术总监架构形态（单 Agent+工具）、技术栈、回滚手册
冶炼专家参数仲裁终审、守恒关定义、领域验收
AI 专家评测门禁标准、模型选型策略、Agent 形态

架构裁决书（本页定稿 · 正文三句）

① MVP 与第一阶段采用"单智能体 + 工具集"：一条编排线，四种工具（引擎/知识库/判例/回放）。理由：审计链清晰（安全红线②）、延迟可控、错误域单一；多智能体的 Actor/Validator/Reprompter 三角作为对话形态在同一个编排线内演进（P2 起 Validator 独立成服务），而不是一开始就分布式。

② 界面走"三视图"路线：驾驶舱（操作工）/ 仲裁台（专家）/ 治理台（管理员），MVP 只做驾驶舱+仲裁卡。答案三要素与红黄绿置信度为验收硬条款（沈工否决权生效中）。

③ 触达形态：MVP=本地 HTML + P2=内网 Web + P3=车间大屏/移动端加报。模型先走云端强模型（若数据出海被否，直接启用厂内小模型兜底路线）。
