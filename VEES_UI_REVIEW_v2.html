一、敏感性分析的作用与解读

作用

固定其他开吹条件，单独扫描一个输入参数（当前实现：铁水 Si 含量 0.10%→0.30%），观察输出（预测精钒渣 V₂O₅ 品位）如何随之变化，画出"输入→输出"的机理响应曲线。它是工艺专家判断哪个参数最该盯紧、参数逼近哪个值时品位会跌穿目标的决策依据。

解读要点（对应 03 模块）

  • 曲线下行段 = 硅稀释敏感区：Si 每升 0.01%，品位约降 0.2–0.3 个百分点。机理是 Si 氧化产生的 SiO₂ 作为脉石进入炉渣，稀释了 V₂O₅ 的质量分数。
  • 蓝色虚线 + 圆点 = 当前铁水条件落点：把当前 Si 滑杆值映射到曲线上，一眼看出当前品位处在曲线的平缓区还是陡降区。
  • 斜率 = 敏感度：陡的地方说明该区间 Si 微小波动就会显著影响品位，炉长/工艺专家要重点控制；平缓的地方容忍度高。
  • 三模块联动：03 给"趋势"，02 给"当前点数值"，05 给"口径选择对当前点的影响"——三者共同支撑工艺专家的复核决策。
局限：当前仅扫 Si 单参数；V、T 的敏感性曲线未画；多参数联合敏感性（如 Si×V 交叉）未建。属 P2 扩展。

二、四维评审综合（结论先行）

总体判断：视觉层级与反馈即时性优秀（UX），引擎移植准确（数据，黄金 11/11），rAF 节流充分（性能），全屏 CSS 驱动零重算（性能）。但挖出 1 个真 bug（热量单位差 1000 倍）、3 个边界崩溃点（空数组/坐标溢出/留痕丢失）、1 组性能冗余（72 次 runModel 可压到 ~20）、3 个 UX 隐患（缺二次确认/留痕仅内存/列底触达低）。

3. 性能影响角度

实测：单次 update 触发 72 次 runModel（主1 + drawSweep 21 + arb alt 1 + rmse×2 各16=32 + drawReplay 16 + goldTB 1）。runModel 纯算术单次 <1ms，72 次约 5–8ms，rAF 合并下连续拖滑杆不掉帧。

arb 两次 rmse共 32 次，结果只依赖 dhV，与滑杆无关dhV 切换时算一次缓存P1 -32 次

剔除冗余后单次 update 可从 72 次压到 ~20 次（甚至 ~5 次）。当前不卡，但为后续多参数扫描留余量。

其他

  • 内存：opLog 上限 12 条→已修提到 50；_tweens Map 6 key 正确回收，无泄漏。
  • 演示模式：850ms 合理；但 tab 切走后定时器仍按 850ms 触发（rAF 后台被节流到 ~1s），建议 visibilitychange 暂停省电。
  • 全屏：仅切换 body.fs class + Fullscreen API，零重算，性能优秀。

  • 热量单位：02 KPI 与 05 arb 表"热量富余（MJ）"→"（GJ）"，修正 kJ/1e6 应标 GJ 的 1000 倍差错（数值逻辑不变，仍 16.5）。
