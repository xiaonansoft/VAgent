03核心交锋：六个议题

每个议题呈现立场原话 → 分歧点 → 会议结论。结论栏标注共识等级与证据支撑。

交锋议题一 · "智能体"到底是什么？

是套壳 LLM 的对话助手，还是一个能闭环的工业决策系统？
林深AI 架构

按业界定义，Agent = 感知 + 规划 + 工具调用 + 反思。LLM 是"认知外壳"：理解操作工的自然语言提问、选择工具、组织解释。但我不接受"端到端大模型炼钢"——没有任何一家敢把温度设定值交给采样出来的 token。

高韧冶炼专家

我补充一个三十年前的参照：90 年代的静态控制模型 + 副枪动态修正，本质上就是"感知-认知-决策-执行"闭环，只是"认知"是查表和微分方程。今天的增量不在"智能"两个字，在三件事：机理内核的精度、经验知识的治理、解释的可信度。谁吹大模型替代机理，谁的系统活不过一次炉渣返干。

沈炉工艺专家

从炉前视角补一刀：智能体最值钱的时刻不是开吹前算配料，而是异常来临的 90 秒——喷溅前兆、脱碳速率突变。这时候它要能在 10 秒内告诉我"现在发生了什么、按你现在的枪位下去会怎样、上一炉同样征兆是怎么处理的"。这要求它同时接住实时数据流和历史判例。

会议结论（强共识）

VERO = 认知外壳（LLM 编排/解释/检索） + 确定性内核（机理引擎 + 规则引擎，垄断一切数字） + 学习闭环（误差回流） + 人在环（决策权）四层。LLM 永远不产出生产数字，只做四件事：解释、检索、what-if 编排、把专家口语转成规则草稿（人工审批后入库）。

共识+实证议题二 · Excel 专家经验如何资产化？

秘诀躺在 703 个公式的单元格里，怎么变成系统能治理的知识？
苏呈知识工程

方案已经跑通了一遍：Excel → 解码报告 → Python 参考实现 → 黄金用例回归 → YAML 知识包（含溯源/审批位）→ 一致性校验器。关键设计是"单一事实来源"——引擎只从知识包取参，谁也不许在代码里私藏一个 22.5。

高韧冶炼专家

我审一遍就要问三个问题的：这个 1.157 是哪个厂哪类铁水得来的？季节修正有没有？极限工况外推到哪失效？知识包里每个参数必须带适用边界字段，否则就是新的黑盒。

何稳功能安全

补治理要求：IP 分级（配方级机密加密存储、流程级知识才进 RAG）、shadow mode（新规则包并行跑不生效）、判例库（每次人工仲裁入库，同类冲突预填历史倾向但永不自动决定）。

会议结论（已部分落地）

知识包五级级联（行业基线 → 厂 → 车间 → 炉座 → 炉次学习值）；每参数带溯源单元格 + 适用边界 + 审批流；冲突仲裁 = 双方案对照 + 历史证据 + 人工决策位。已完成：31 类参数入库、6 条冲突登记、一致性校验器。

共识+实证议题三 · 机理模型 vs 端到端数据驱动？

有了几千炉生产数据，要不要训一个端到端模型直接预测终点？
赵数数据科学

反对。样本量支撑不起端到端，而且外推必崩——原料一变模型就哑。正确姿势是灰箱三层：①机理打底（守恒方程）②数据只学残差修正（RLS 更新热效率因子）③按 Si/温度聚类维护参数库。我们 16 炉次反演也证明了：光调一个 ΔH_V，RMSE 只能从 1.47 降到 1.00，剩下的偏差要靠逐炉工况数据，不是靠换模型结构。

高韧冶炼专家

同意，加一条硬约束：任何学习结果必须通过守恒校验才能上线——物料差、热差、钒平衡三道关。专家A那个 93 MJ"富余"最后查出是表格漏项，就是守恒校验的价值。数据修正不许破坏物理。

赵数数据科学

再补个数据基建提醒：现在 Excel 只有 16 天的日均值，粒度太粗。要接炉次级数据（TSC/TSO 副枪、烟气分析、氧枪曲线），否则残差学习没有训练对。时序库选型先别激进，PostgreSQL 分区表够用一年。

会议结论（强共识）

灰箱路线：机理内核（已复现至 0.0002%）+ 残差学习（RLS）+ 分聚类参数库 + 漂移检测（3σ 触发重校准）。学习结果上线前过三道守恒关。端到端 ML 降级为远期研究项。

交锋议题四 · 编排框架与 RAG：用现成的还是自研？

LangGraph 已在代码库里，要不要换？知识库怎么建才不被 LLM 污染？
林深AI 架构

保留 LangGraph，理由：状态机语义清晰（配料→仿真→校验→诊断的 DAG 天然适合）、checkpoint 可回放（炉次就是天然 state）、多智能体角色已经建好。自研编排是重复造轮子，省下的精力投给工具层纪律：MCP 工具服务器（已有雏形）+ 每个工具返回结构化事实 + trace_id 贯穿。RAG 上做混合检索（向量 + BM25 + 结构化规则路由），但索引对象是已审批的知识包条目和规程片段，绝不让 LLM 直接检索原始 Excel——防止配方级 IP 被对话套出。

沈炉工艺专家

我不管什么框架，我只要求回答里必须有三样东西：引用哪条规则（版本号）、哪个相似炉次、什么物理依据。做不到的答案，界面直接标"未经核实"。

林深AI 架构

这正是约束式生成该干的：回答模板强制包含 rule_ref / similar_heat / mechanism 三个字段，字段内容由引擎填充，LLM 只负责串联语言。做不到就拒答——比幻觉强。

会议结论（共识，附沈工否决权）

LangGraph + MCP 保留；RAG 索引已审批知识 + 规程，IP 分级访问；回答强制三要素（规则版本/相似炉次/物理依据），缺失即标注"未经核实"。模型选型：云端强模型做交互 + 厂内小模型兜底（断网可用），不做冶炼语料微调（收益低），优先保工具调用能力。

交锋议题五 · 人机边界划在哪？

系统建议 → 操作工执行，这个链条上哪里必须有人？
何稳功能安全

划三条红线：①LLM 输出永远不进控制回路（只进人机界面）；②设定值下发必须人确认，系统记录"谁、依据哪个版本规则、何时"；③新知识/新参数默认 shadow，新旧并行输出对照至少 N 炉，专家确认才切换。另外要设计"拒绝服务"：传感器置信度低于阈值时，系统应该说"我不可信"而不是硬给数。

沈炉工艺专家

加一条来自现场的：例外通道必须有。"本炉例外"按钮——操作工凭经验驳回系统建议，但要留一句话理由。这句理由金贵：例外频发的规则就是该修订的规则，系统要自动把例外率报给专家委员会。

高韧冶炼专家

最容易被忽略的：模型也要有"认错"机制。终点实测出来后，误差必须自动回流更新参数——现在的 Excel 做不到这个，它的经验停在 2024 年。系统必须保证经验是活的。

会议结论（强共识）

三条红线 + 例外通道 + 误差自动回流。仲裁/例外/修订三张记录构成"活的专家经验"闭环：Excel v2024（静态）→ 系统判例库（持续）→ 规则包修订（人审批）。

开放议题六 · 多厂多车间的终局形态？

专家A、专家B、未来其他厂——一套系统还是各起炉灶？
苏呈知识工程

架构上已经准备好答案：知识包级联让"新厂 = 一份 override YAML + 历史回放验证"。真正的难题是数据与 IP 治理：专家A的秘诀包和专家B的经验包能不能放同一个实例？我建议物理隔离（每厂独立知识库）+ 仲裁判例脱敏共享（只共享冲突类型与决策模式，不共享参数值）。

赵数数据科学

学习层同理：参数库按厂隔离，但漂移检测的统计方法、聚类策略可以共享。跨厂联合建模是远期选项，前提是拿到双方数据授权。

会议结论（方向共识，细节待定）

一套代码 + 每厂独立知识包/参数库/判例库；判例模式脱敏共享。部署形态：厂内私有化（Docker Compose 已有基础）。该议题在 P3 阶段重开，先把手头单厂闭环做穿。
