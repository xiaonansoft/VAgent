VEES 界面重构方案 · 四路智能体评审汇总

对象：VEES_MVP_v0.6.html · 方法：UI 设计师 / 前端工程师 / UX 研究员 / 设计总监 四路并行独立评审，主智能体汇总裁决 · 2026-09-27

一、总体判断（结论先行）

核心诊断（四路一致）：当前界面是「GitHub Dark 皮肤 + 电竞发光特效包」的拼贴品，不是工业金属感。
色板直接沿用 GitHub Primer 原值（#0d1117/#161b22/#30363d/#58a6ff），再叠加熔融橙发光、LED 脉冲、L 形角标、网格底纹——视觉锚点在「科技 SaaS 仪表盘」，不在「冶金生产决策终端」。骨架（信息架构/角色分层/引擎/缓存）是产品级，视觉系统是拖后腿的那一环。
评审视角评分一句话判断
UI 设计师（视觉设计系统）5.0/10信息架构合格但视觉系统失控：12+ 种间距值、5 种圆角、4 处发光机制、橙蓝双主色平权对抗。删掉一半装饰，留下一倍可信。
前端工程师（实现质量）6.5/10缓存/rAF 节流/留痕持久化体现工程意识；但内联样式失控、innerHTML 拼接有 XSS 面、可访问性近乎为零。视图层还是原型级。
UX 研究员（体验与信息架构）6.5/10动线骨架正确，但 02 卡 7 层状态信号叠加、「10 秒读数」承诺与信号冗余度不符；黄灯证据卡在按钮之后违反「先证据后决策」。
设计总监（方向与行业适配）4.5/10设计语言错位：无金属材质隐喻、发光即炫技、无使用场景概念（1.5m 视距/投屏形态缺失）。停止在发光程度上迭代。

P2 — 打磨项

  • 正常建议语 .say 占用品牌橙，告警黄反而权重更低 → 正常态中性卡片，橙只给主 KPI/CTA
  • 两张 .kpi.hl 同尺寸同 glow 无主次 → 配吃（决策对象）> 品位（校验指标）
  • 演示横幅橙条与黄灯色温相近 → 改蓝色系或描边
  • RMSE 裸数字无参照系 → 加解读句"相当于品位平均偏差 ±Ypp"
  • 相似度"越小越相似"反直觉 → 归一化 0–100%
  • 黄金回归全绿时 11 行证据过载 → 默认折叠为摘要条"11/11 通过·最大误差 x%"
  • _tweens Map 动画结束未 delete → 轻微内存泄漏，补 delete
  • warnCase display 切换致布局抖动 → visibility 预留占位
  • h1 letter-spacing 1px 偏大 → 0.5px
  • grid-top 三列 px 定宽 → fr 比例 + minmax 随视口流变

三、重构方向选项（设计总监三案）

A 收敛克制派B 工业仪表派 推荐主体C 数据终端派
参照Linear / GitHub Dark（去发光版）航空座舱 / 船舶驾驶台 / ABB AbilityGrafana / Bloomberg 终端
核心特征单锚色、零发光、1px 灰线、大留白刻度盘/量规语汇，读数即仪表，厚重面板高密度表格+迷你图，等宽数字
色板底 #0e1113 / 卡 #16191c / 锚橙 #e8611a底 #101214 / 黄铜刻度 #c8a44d / 熔橙只做告警与关键读数纯灰阶 + 橙红绿三信号色，无蓝
取舍砍 LED 脉冲/角标/网格/glow/滚动动画砍 SaaS 圆角卡片和渐变；配吃量做量规、温度做刻度条、红绿灯做实体灯质感砍插画化装饰/emoji；判例库密表
风险最"安全"但可能被评"普通"做好是 ABB，做差是蒸汽朋克 cosplay，实现成本最高对炉长不够友好，首屏过载
推荐度★★★★☆（作底座）★★★★★★★★☆☆（留给数据治理台）
最终推荐：B（工业仪表派）为主体 + A（收敛克制）为底座 = 「克制的仪表」。
整体遵循 A 的零发光、零纹理、五级字阶纪律；在炉长驾驶舱的两个核心读数（配吃量、品位预测）和红绿灯状态上用 B 的仪表语言做出物理厚重感（刻度、量规、实体灯）；C 的信息密度美学留给数据治理台。
理由：钢厂用户信任"朴素可靠"，但朴素不等于"像 Linear"——真正的高级感来自仪表的确定感：带刻度、指针干脆、数字稳如磐石的界面，才是 1500℃ 场景的对等物。发光和网格从来不是工业，刻度才是。

四、设计系统规范（v0.7 目标态）

色板（9 色封顶）

底色:  --bg:#0b0d10  --surface:#12151a  --raised:#181c22
描边:  --line:#262c34  --line-hi:#3a424c(hover)
文字:  --t1:#e8ecf1  --t2:#9aa4ae  --t3:#5f6873(仅装饰)
品牌:  --accent:#e8620f (仅主KPI/CTA/告警强调)
语义:  --ok:#4a9e5c --warn:#c99a2e --danger:#d9534f
信息:  --info:#6b93b8 (低饱和，图表第二序列)
原则：橙/蓝饱和度压 15-20%，向"烧蚀金属/炉膛余温"靠，而非霓虹灯管。告警色是唯一高饱和色。

间距 / 圆角 / 字级

间距（4pt，6 档）: 4 / 8 / 12 / 16 / 24 / 32
  面板 padding 16 · 卡内 12 · 面板 gap 16 · 区块 24
圆角（3 级）: 面板 8 · 控件 6 · 徽章 pill
字级（5 级 + 数字规则）:
  display 32/700 · h1 20/700 · h2 15/600
  body 14/400 · caption 12/400
  数字一律 tabular-nums（不单独换 monospace，
  等宽只留给溯源/日志 .mono）
投屏档（独立媒体查询）:
  正文 ≥18 · KPI ≥48 · 辅助 ≥13 · 触控 ≥44px

装饰预算（硬规则）

  • 每屏发光元素 ≤ 1 处（当前告警态）；无限循环动画 ≤ 1 个
  • 删除全部 L 形角标 / 网格底纹（或 opacity ≤.015）/ 数字滚动动画 / emoji 图标
  • 金属感 = linear-gradient(180deg,#181c22,#12151a) + 顶部 1px rgba(255,255,255,.04) 内高光——哑光钢板，不是亚克力灯牌
  • 信号分级：状态只 1 个主信号（badge）+ 1 个行动文本；KPI 变色仅保留品位破限一种语义

组件 token（5 个，贯穿三层视图）

token规范
panel8px 圆角、1px --line、16px padding、顶部内高光、无阴影无角标
kpi / gaugetabular-nums 大数字；炉长双核心读数做量规式（配吃量带刻度标尺、品位带 14.0 门限刻度线）
status-light静态常亮；仅黄/红允许 ≤0.5Hz 慢闪；颜色+文字双通道（色盲安全）
table1px 线、表头 --raised 底、数字 tabular-nums 右对齐；数据台可加密度档
input-slider拇指 ≥32px 带刻度；配数字直输（点击 .val 可编辑）+ ± 微调按钮

五、实施路线图（三步走）

第一步 · 清零（半天）—— 让界面"安静下来"

  1. 删除全部 glow/pulse/text-shadow/drop-shadow/L 角标/网格底纹/emoji/数字滚动动画
  2. 色板整体降饱和，橙只保留锚色+告警，蓝降级低饱和
  3. 字级收敛 5 级、圆角收敛 3 级、间距收敛 4pt

第二步 · 立骨（1-2 天）—— 仪表语言 + 场景适配

  1. 桌面/投屏两档字阶；滑杆改 32px+ 拇指带刻度 + 数字直输
  2. 炉长视图重构：两栏布局、双核心读数量规化（配吃量主 36px / 品位校验 24px 带门限刻度）、4 次级 KPI 收折叠、右列说明书首访后折叠
  3. 黄灯证据卡上移至按钮前；黄灯文案行动化（哪个参数/超多少/核心动作）
  4. 口径选择收归工艺台（炉长侧只读灰字）；仲裁按钮加终态并回写
  5. 品位 KPI 三色门限态；状态信号收敛为单点信号源

第三步 · 定型（2-3 天）—— 工程还债 + 验收冻结

  1. CSS 三层 token 收敛（硬编码色值归零）；update() 依赖分层；SVG 静动分离；esc() 防 XSS
  2. 可访问性清单全落地（aria-label/focus-visible/双通道/reduced-motion/SVG 语义化）
  3. 工艺台编号理顺、RMSE 加解读、黄金回归折叠摘要；数据台套 C 案密度规范
  4. 验收：1366 桌面 + 1920 投屏双分辨率实拍，1.5m 视距可读性达标后冻结视觉层
保留不动（已是产品级）：引擎与黄金基准 11/11、性能缓存机制（72→1 次/帧）、留痕 localStorage 持久化、三层角色视图的信息架构骨架、信任锚"区间+落点"结构、解释卡三段式。本次重构只动视觉层与交互层，引擎与应用逻辑零改动。
