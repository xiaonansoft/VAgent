二、定位修正：边界 2 怎么改

冲突：docs/PRODUCT_DEFINITION.md v1.0 边界 2 写「只开吹前，不碰事中」，与本次三段式规划直接冲突。
边界原文修订建议
1只决策支持，不碰执行——建议权在用户；系统输出永不直接下发控制回路不动 这条是功能安全红线，也是唯一的免责锚点
2只开吹前，不碰事中——吹炼动态控制属 P3，产品名片上不写修订 →「事中只推理与建议，不执行；过程自动闭环控制仍属 P3，名片不写」
3所有数字带证据链——规则版本 + 物理机理 + 相似炉次不动 扩展到中段：每个实时建议同样带三要素 + 置信
为什么不是"另起一份 roadmap 绕开"：绕开的代价是中段永远拿不到工程投入，而中段恰是数据密度最高、最能形成壁垒的一段。正确做法是改边界 2 的措辞，把"不碰事中"精确化为"不碰事中执行"——原文档的意图本来就是防越权，不是防推理。
对外话术同步：禁用词保留「AI 炉长 / 智能炉长 / 全自动」，新增禁用「自动提枪 / 自动配加」，改用「终点判断建议 / 优化建议 / 干预窗口提示」。

三、冶炼前预测（开吹前 30~90 秒 · 一次性求解）

现场此刻：铁水成分温度刚到、二助手报冷料、天车待命，炉长定氧量与配吃量。数据源 = 化验单 LIMS（时延 3~15 min）+ 称量斗 PLC + 人工录入。

四、冶炼中监控并预测（8~12 分钟 · 1 秒级滚动）★本次重做

现场此刻：一助手控枪位与氧流量、看火听声；无在线连续测温，终点只能等化验。中段的价值不是"看"，是提前几分钟知会跑偏，并说清现在还来得及做什么。

实时推理闭环（五步，每秒一轮）
① 采集：枪位、氧流量、吹氧时长（PLC 1s）＋ 副枪 TSC/TSO 离散点（1~2 次/炉，时延 30~60s）＋ 烟气 CO/CO₂（1~5s，唯一能反算 dC/dt 的硬源）＋ 称量斗实绩
② 状态估计：8 维 ODE 递推（C / Si / V / Ti / T / FeO / V₂O₅ / SiO₂）＋ 卡尔曼同化观测
③ 滚动预测：从当前状态前向积分到吹炼终点 → 终点温度、残 V、半钢 C、V₂O₅ 品位，带置信带（KF 协方差）
④ 偏差检测：实际轨迹 vs 开吹方案（S2 那条线），偏离度红黄绿
⑤ 优化建议：枪位 / 氧流量 / 补加冷却剂 / 提枪时机，每条附剩余干预时间窗

F2.6 为什么是中段第一价值点：提钒是"边吹边升温、靠冷料压温"的过程，遇上铁水温度偏高，开吹前的方案就需要中途修正。但只有散状冷料（称量斗路径）具备事中补加的执行通道；块状冷料走天车吊运 2~3 分钟、接近吹炼全程的 1/4~1/3，且有喷溅风险，事中追加基本不可执行——所以块状料的正确做法是在 F1.2 开吹前一次配足，把"事中不可追加"作为约束算进配吃方案。没有这条，中段就只是仪表盘。
但要诚实：① 块状冷料实吊量不回传，算的量 ≠ 实际入炉量，证据链断；② 散状补料建议必须带"窗口一过自动失效"机制，绝不出马后炮建议。

九、边界：做什么 / 不做什么（红线）

做（可写进合同与投标）不做（红线，越界即责任事故）
开吹前配吃建议与品位预测（带置信）写入 DCS / PLC —— 任何形式
三要素证据链、双口径对照、判例库自动闭环过程控制（自动提枪、自动配加、自动调氧）
冶炼中实时推理：状态估计 + 滚动终点预测承诺保品位、保收得率、保收益
冶炼中优化建议 + 干预时间窗提示代裁 CF-001（ΔH_V 2777/15000，属甲方权威裁决）
冶炼后复盘归因、偏差带统计、漂移告警在线自动改参数（含"自学习"字样一律不用）
只读留痕 + 人工确认 + 版本治理，数据不出厂跨厂共享厂级经验与标定参数
最容易踩的一句话：把"优化建议"讲成"自动优化"。建议 = 决策支持，自动 = 越权执行。对外物料里凡是出现"自动投料 / 自动提枪 / 自动调节"，一律删除。
