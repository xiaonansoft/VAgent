# VERO MVP v0.1 规格 (SPEC)

> 依据: 第三轮行动计划 D1-D5 排期 · 四席拍板（产品/技术/冶炼/AI）
>> 形成日期: 2026-09-23 · 状态: v0.1 待签认

## 1. 形态裁决（已定稿）
- **单一智能体 + 工具集**（编排线一条；Actor/Validator/Reprompter 三角作为 v2 内该线的演进形态，不分布式）
- **交付形态**: 本地单文件 HTML（浏览器即跑、离线可用、IP 不出厂）——冶炼模型引擎由 Python `plant_a_reference.py` 忠实移植为 JS，常数仍由 `knowledge/packs/plant_a/base.yaml` 单一事实来源人工同步（yml 漂移风险记录在案）
- **MVP 不做**: 多用户/联网/大模型接入/写库；这些在 P2，用本 MVP 验收后接

## 2. 角色
- **驾驶舱（操作工/炉长）**: 输入铁水条件 → 看推荐与解释
- **仲裁（专家）**: CF-001 V 氧化热双方案对照 + 16 炉实绩证据
- **自检（技术）**: JS 引擎 vs Python 黄金值回归面板

## 3. 验收硬条款（验收 = 全绿）
| # | 条款 | 判据 |
|---|---|---|
| A1 | JS 引擎黄金回归 | ≥9 个黄金点（品位/配吃/富余/渣/钢/氧耗/双凝固点/物料差）误差 <0.01% |
| A2 | 三要素解释卡 | 规则版本/物理机理/相似炉次 每次渲染 100% 覆盖 |
| A3 | ΔH 仲裁切换 | 2777/15000 切换 → 配吃量与品位即时重算，双案并排 |
| A4 | what-if 曲线 | Si 0.10–0.30 扫描品位曲线实时重算 |
| A5 | 16 炉回放 | RMSE 面板与 Python 校准脚本一致（粗渣 1.466 / 1.000 附近） |
| A6 | 安全-离线 | 全部 <script> 内联、无外链请求；单文件 sha256 可锁定 |
| A7 | 演示流 | <10 分钟走完 输入→推荐→解释→仲裁→回放 |
| A8 | 三要素与置信度 | 输出卡片带 红黄绿 置信度标签（MVP 用静态规则） |

## 4. 明确不做（本轮 scope 外）
- 声音/视频输入；写库；登录鉴权；多语言；枪位 L2 推演（P3）

## 5. 后续演进挂点
- 引擎 JS = P4 前端同源内核，后续换 Python API（一致性靠同一黄金集门禁）
- 16 炉数据 → P3 换成真实炉次台账接口
- ΔH 卡 = 仲裁工作台第 1 个真实用例
