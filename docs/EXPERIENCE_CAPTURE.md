# 师傅经验「对赌式」采集机制（EXPERIENCE_CAPTURE）

> 适用范围：贵溪试点（PS 转炉 5 号炉）｜版本 v1.0｜日期：2026-09-27
> 上位依据：七角色多智能体评审《数字班组对标分析》B9 条 ——「没有经验确权机制，沉淀下来的 Skill 全是规程文件，值钱的默会知识一丝进不来，数字员工上限＝熟读规程的新手」
> 关联文件：`VERO_ACCEPTANCE_WHITEBOOK.html`（验收 KPI/推翻判定）· `VERO_NARRATIVE_KIT.html`（对外叙事口径）
> 术语约定：知识包对外称「**提钒岗位能力包**」；跨厂一致层称「**行业通用**」层；VERO 是面向提钒冶炼行业的**行业级产品**，不是单厂定制。

---

## 0. 一句话说清这套机制

**师傅把脑子里的东西讲出来 → 我们把它写成可以被数据检验的假设 → 判例检验通过才准进会议室级别的包 → 进包后署他的名、记他的采纳账 → 月度会公开念名，并且他讲的这条如果后来被证明是对的，免责记录同步生效。**

这条链路解决三件事：**默会知识进得来**（采集）、**进来的东西是真的**（对赌校验）、**师傅愿意一直讲**（确权与荣誉）。

> 设计红线：本机制**不涉及任何现金奖励**。国企适配原则 —— 发「面子 + 免责」，不发钱。

## 1. 采集什么：四类默会知识

规程抄不来、机理算不出、只长在师傅身上的东西，全部归入以下四类。

| 类别 | 典型内容 | 为什么值钱 | 采集难度 |
|---|---|---|---|
| **A. 火焰判别** | 炉口火焰颜色/亮度/长度/形状与炉内温度、化渣、碳氧反应的对应关系；"火焰发白偏短时大概到了"这类窗口判据 | 属于只能在现场学、书本上找不到的一致性窗口判据，直接影响提枪时机 | 高（难量化、易变） |
| **B. 声音判别** | 炉内声响（化渣声、喷溅前兆声、氧枪异常声）的频率/闷响/爆裂感判断 | 与喷溅预警强相关，是安全类经验 | 高（受环境噪声影响大） |
| **C. 异常前兆** | 温度曲线形态、供氧压力微变、烟气成分漂移、冷却剂加入后反应的异常节奏 | 早于报警信号出现的"手感"，可以在分钟级提前预警 | 中高 |
| **D. 例外处置** | 高硅、铁水成分偏离、设备小故障、化验滞后等条件下的"怎么办"，含优先级与放弃项 | 例外处置决定损失大小，年轻人最容易在这一步出错 | 中（有案例可讲） |

**不采集清单（明确排除，避免污染）**
- 已在操作规程文件里写得清楚的内容（那是**规程条目**，走知识包正常维护，不走本机制）
- 无边界条件的绝对结论（例如"一定要多加球团"——没有前提条件的经验不可判例校验）
- 涉及其他岗位/他人的评价性内容（防止采集变告状会）

## 2. 怎么采：三条通道

### 2.1 通道一 · 结构化访谈（主通道，每次 30–45 分钟）

**访谈模板（一字不改地填，别改写成故事）**

| 字段 | 填写要求 |
|---|---|
| 条目 ID | `EXP-<炉座>-<序号>` |
| 类别 | A 火焰 / B 声音 / C 异常前兆 / D 例外处置 |
| 触发条件（我看到什么） | 必须具体可观测：**"某某量的读数/某个现象/某个时间点"**，不接受"感觉不对" |
| 师父的判断（我认为是什么） | 一句话，不超过 30 字 |
| 我会怎么做 | 动作序列，含先后顺序 |
| 适用边界 | **哪些情况不成立**（这一栏空着不收） |
| 反例 / 上次不准是什么时候 | 必须至少讲一次失败经验，否则本条目标记为「不可信」 |
| 置信度自评 | 高 / 中 / 低（师父自己填） |
| 贡献人 | 姓名 + 工号 + 班组 + 炉龄 |
| 记录人 / 日期 | 采集者签字 |

> 访谈纪律：**先问反例，再问正例。** 如果一上来问"您一般怎么做"，得到的是规程背诵；问"上一次判断错是什么情况"，才开始进入默会层。

### 2.2 通道二 · 班后 5 分钟口述（低成本、高频次）

- 载体：中控室一台录音终端（或手机录音笔），班后会前按下即录，**只录 5 分钟**，三个问题：
  1. 今天哪一炉和以往不一样？
  2. 你是怎么判断的、什么时候判断出来的？
  3. 如果再来一次，你会改哪一步？
- 由工艺员当天转写为上述模板条目，**48 小时内回拿给本人确认一次**；本人确认后条目才算成立。
- 目标频次建议：每个班组每周不少于 2 条（**目标值 · 示例**，实际以试点排班确定）。

### 2.3 通道三 · 留痕对照复盘（最有价值的一条）

把师父的口述与**系统留痕**（建议值 / 实际值 / 推翻记录 / 终点实绩）摆在同一屏上逐炉复盘：

- **师父推翻了建议的地方** → 追问"你当时看到了什么" → 直击默会知识核心；
- **师父没推翻但结果不好的地方** → 追问"当时有没有觉得不对" → 提取未成形的手感；
- **推翻后被判定为"推翻正确"的炉次**（由机理引擎自动回溯判定，不由人拍板） → **优先采集**，命中率最高。

> 这条通道把采集成本压到最低：不需要额外组织一场会，用已有留痕当提纲。

## 3. 怎么确权：署名、记账、光荣榜

### 3.1 经验署名

每一条入库经验在知识包中携带贡献人字段：

```
contributor: { name: "[姓名/工号]", crew: "[班组]", created: "YYYY-MM-DD" }
citation:    "[来源：口述访谈 / 班后口述 / 留痕复盘]"
```

- **署名跟着条目走**：该经验被调用出现在建议证据区时，界面在**证据区**显示"经验条目 EXP-xxx（贡献人：[姓名]）"——**只在查阅性区域显示，不作为决策主语**（零人格化留痕规范仍然生效：决策主语永远是"系统/机理引擎/模型 vX.X"）。
- **署名不可删除、不可转让**：条目被修订时，原贡献人保留并追加"修订贡献人"。

### 3.2 采纳记账

每条经验建立一本公开账：

| 记账项 | 说明 |
|---|---|
| 入库日期 | 进入候选项的日期 |
| 判例校验结果 | 命中 / 命中 / 未命中（见 §4） |
| 被调用次数 | 该经验参与建议生成的次数（只统计真实生产态） |
| 采纳后效果 | 采纳该经验的建议之后，对应炉次终点命中情况 |
| 当前状态 | 候选 / 已入包 / 已降级 / 已废弃 |

> 记账面板挂在工艺台，**所有人可见**。这是"资产感"的来源：师傅能看到自己的经验在被用、用了多少次、准不准。

### 3.3 月度光荣榜（不发钱，发面子）

月度生产会上设固定议程「**经验资产月度榜**」，念三种名：

1. **贡献榜** —— 本月入库条目最多的班组/个人；
2. **命中榜** —— 本月采纳记账中"命中"次数最多的经验及其贡献人；
3. **纠偏榜** —— 本月被判定"推翻正确、且该推翻被证明对"的操作人员（与白皮书双轨 KPI 的质量轨同源）。

配套两份**书面产出**：
- **月度榜单张贴**：中控室公告栏 + 班组群里的一张图；
- **优秀经验通报**：以车间名义下发的一份 1 页通报（可用于个人评优材料）。

### 3.4 与班组绩效的非金钱挂钩方式

> 原则：**挂荣誉、挂机会、挂便利，不挂钱。** 以下条目须经厂方人力资源/车间口径确认后启用，列出的是选项池，不是全部执行。

| 挂钩方式 | 具体做法 | 备注 |
|---|---|---|
| **免责记录** | 该经验判定为正确但现场按经验执行后仍出现异议时，凭留痕免责；反过来，判定正确的推翻同步生成免责记录 | 一线最看重的一项（源自"不追求奖金，追求被推翻的权利制度化"） |
| **评优加分** | 年度/季度评优、技师评聘申报材料中的"知识传承贡献"事实依据 | 需写入车间评优细则 |
| **培训名额** | 外出培训、技术比武、交流学习的优先推荐权 | 成本低、感知强 |
| **带徒资格** | 获得"带徒/授课"资格，在班组里自然获得地位 | 直接命中"老师傅要面子" |
| **免检名额** | 所属班组获得月度台账抽查减免 | 由车间自行确定是否可行 |
| **命名权** | 高频命中的经验条目以"某某操作法"命名并在全车间推广 | 荣誉峰值，慎用、只用在高价值条目 |

## 4. 怎么入包：经验 → 假设 → 判例校验 → 入包登记 → 回归测试

### 4.1 五步制流程（每步有出口条件）

| 步骤 | 做什么 | 出口条件 | 负责角色 |
|---|---|---|---|
| **S1 录入** | 按 §2 模板落到条目表 | 触发条件可观测、边界明确、有反例记录 | 工艺员 + 师父本人签字 |
| **S2 假设化** | 把口述转成**可检验命题**：在什么条件下、观测到什么、应当采取什么动作、预期结果是什么 | 命题有明确的**判定数据来源**（终点温度/终点碳/喷溅记录/化验实绩之一） | 行业专家 + 工艺工程师 |
| **S3 判例校验** | 拿历史炉次判例回该命题：符合的条件下，命题指示的动作与实际结果是否一致 | 命中率达到双方约定的阈值；阈值由试点基线确定（**目标值 · 待采集**） | 机理引擎自动回溯判定，**不由专家拍板** |
| **S4 入包登记** | 通过校验的经验写入「提钒岗位能力包」经验层；凡与其他口径冲突的，**登记为 CF 条目**（沿用 CF-001~008 登记册体系，编号续编） | 有版本号、有 contributor、有 citation、有适用范围 | 知识包管理员 |
| **S5 回归测试** | 每次入包/变更必跑 | 四大平衡黄金回归维持 75/75 / 误差 0.0002% 基线；parity 双端一致（JS 移植 11/11）通过 | 开发 + 自动化脚本 |

### 4.2 「对赌」到底赌什么

这是本机制的核心，也是**对抗"经验采集热热闹闹但不可信"的唯一手段**：

| 参与方 | 下什么注 | 赌赢得到什么 |
|---|---|---|
| **师父** | 押上自己的判断：这条经验在历史判例里站得住 | 署名 + 采纳记账 + 月度榜 + 班组的荣誉名额；**命中率越高，署名含金量越高** |
| **采集团队** | 押上工程的严谨性：保证假设化不歪曲原意、判例校验口径不被人为挑选 | 知识包真实增值；经不起检验的经验不予入包 |
| **系统** | 押上机制的可信性：判定由机理引擎自动回溯，**双方都不允许手工改判定结果** | 争议一次性消失 |

**三条对赌纪律**
1. **判定必须能被复算**：每个校验结果留 `trace_id`，谁都可以拉出来重放。
2. **不许挑数据**：校验样本的集合在检验前写死（时间窗、炉次范围、排除规则），**事后不得追加剔除**；这与白皮书 §06 采样规则一致。
3. **失败不罚，只不署名**：命中率不达标的条目降级为「候选/口述档案」，保留但**不进能力包、不署名、不进采纳记账**。对人不做负面评价 —— 否则第二次就没人讲了。

### 4.3 降级与退役

- **已入包条目**若连续两个核算周期表现低于约定阈值（阈值待基线采集），从「已入包」降回「候选」，成为口径复审对象；
- 退役条目保留在历史库中并注明原因（工艺条件变化/设备改造/原料结构变化），**隐匿删除不合规**。

### 5.4 试点验收（可直接写进项目验收单）

| 验收项 | 判据 | 备注 |
|---|---|---|
| 采集量 | 原始条目数量达到约定目标（**目标值待双方确认**） | 不追求数量堆砌，**"有反例+有边界"的才算有效条目** |
| 入库率 | 通过判例校验并正式入包的条目占比 | 阈值**待基线采集后确定**；首轮偏低是正常的，正说明校验没有放水 |
| 确定性底座未受损 | 黄金回归维持 **75/75**、parity 维持 **11/11** | 硬指标，任何一条不通过即回滚本次入包 |
| 一线可接受度 | 认可度问卷/访谈：参与师傅对"署名、记账、光荣榜、免责"四项机制的认可度 | 主观项，作为机制能否推广的决定性依据 |
| 可复算性 | 随机抽 5 条入包经验，现场用 `trace_id` 重放校验过程，结果一致 | 与白皮书 §06 争议仲裁同源 |

## 6. 风险与规避

| # | 风险 | 表现 | 规避动作 |
|---|---|---|---|
| 1 | **老师傅不愿讲** | "讲的都是常识""讲了也没用""教会徒弟饿死师父" | ① 开场先讲清楚**三件事**：署你名、不顶你岗、不为难你；② **免责记录**作为第一卖点（"讲出来的东西，将来真出事时能保护你"）；③ 先采**推翻正确的案例**——他本来就想说"我早说过了"；④ 采集对象从**工龄长者 + 愿表达的**开始，做出样板后自然蔓延 |
| 2 | **经验互相矛盾** | 同炉同工况，两个班组两套做法 | ① **不评判、不调和**，两条各自登记为**冲突 CF 条目**；② 按 S3 用判例数据各自校验，让数据挑出适用边界（常常是"条件不同"而非"谁对谁错"）；③ 双方都保留署名 —— 冲突登记不是打脸，是登记 |
| 3 | **经验错误导致生产损失** | 入包经验给出了错误方向 | ① 入包前必须过 S3 判例校验 + S5 回归；② **建议永远不强制执行**，必须经人工确认（"AI 直发设定值次数＝0"）；③ **责任界定书面化**：经验的判断建议权在系统，决策权与操作权在一线，师傅对入包经验的后果**不承担责任**，由输出方承担；④ 出现偏差立即走 §4.3 降级流程 |
| 4 | **追求数量导致注水** | 月底冲条目数 | ① 明确"有边界、有反例"才算有效条目；② 入库率比采集量更重要，考核指标以**入库数 / 被采纳调用次数**为主 |
| 5 | **口述被采集者改写走样** | 工艺员写成"自己理解的版本" | ① 48 小时内回本人确认并签字；② 变更超过原意的修改必须重新确认；③ 原始录音/笔录归档，`citation` 字段标明来源 |
| 6 | **光荣榜变成少数人的固定节目** | 老是那两位老师傅上榜，其他人躺平 | ① 三类榜单分开（贡献/命中/纠偏），纠偏榜对**年轻人**开放；② 增设月度"新面孔"指标（每期至少 1 位首次上榜者，示例 · 待确认） |
| 7 | **经验涉及工艺机密外泄** | 厂级经验被跨厂复用 | ① 三级 scope：**行业通用（industry）→ 厂级包 → 车间/炉座**；② 厂级默会经验进**厂级层**，默认不进入行业通用层；③ 是否开放跨厂共享，由厂方书面决定，默认不共享 |
