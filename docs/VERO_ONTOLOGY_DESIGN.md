## §0 本体定位一句话

**本体不是新工程，是知识包的语义视图**：在现有 `vero.knowledge-pack/v1` 之上补齐「参数四维注释（value/unit/source/status）+ 冲突节点 + 判例与证据入图」，只覆盖**冶炼前与冶炼后**；冶炼中 10s 动态路径继续走机理引擎直算（文章 2 明确排除高频动态场景用本体，误用会让 10s 路径变慢且难验证）。`resolve_parameters()` 仍是唯一取数点，本体服务不得成为第二真相源。

## §1 痛点（提钒段 + 半钢段）

### 1.1 提钒转炉段（工序一）

| # | 痛点 | 现场表现 | VERO 的对应能力 |
|---|---|---|---|
| P1 | **看不见**：炉内温度/成分黑箱 | 无在线连续测温；终点只能等化验（30min~数小时）；化验时滞 5~8min 还会被当成"实时" | 8 状态 ODE + KF 同化的软测量态估计，数据时龄显式标注 |
| P2 | **控不准**：Tc 稍纵即逝 | 碳钒转化温度（约 1361℃）越过即钒烧损或保碳失败；老师傅靠看火听声 | Tc 热力学推算 + 轨迹前推 + 剩余干预窗口倒计时（误报 ≤1 次/班门槛） |
| P3 | **配不准**：冷却剂配吃靠经验 | 块状料走天车必须开吹前一次配足、散状料走称量斗可事中补——约束不显式就给做不到的建议 | 四大平衡（物料/热/氧/渣）反算总量（专家A）× 品种分配结构（专家B），加料路径进约束 |
| P4 | **难传承**：经验不可复制 | 班次间品位波动大；新工上手慢；好炉次没人复盘 | 三要素证据链 + 好炉次自动入判例库 + 带署名的采纳记账 |
| P5 | **口径冲突无仲裁** | ΔH_V 2777 vs 15000（CF-001，配吃差 520kg/炉）、渣量算法（CF-003）、专家B基准/上限自相矛盾（CF-006） | 双口径并排对照 + 16 炉反演证据 + 冲突清单 API + 人工决策位（系统不代裁） |

### 1.2 半钢脱碳段（工序二，命中率洼地）

| # | 痛点 | 现场表现 | VERO 的对应能力（P2 起步） |
|---|---|---|---|
| S1 | **终点命中率低** | 半钢碳温双命中 80.71%，比普通铁水（90%+）低近 10 个百分点——余钒/残碳波动直接传导 | 复用 SDM 脱碳模型结构 + 三处半钢修正；终点滚动预测 |
| S2 | **跨工序衔接靠人** | 提钒终点→半钢入炉之间无契约：半钢 C/温度/余钒全靠口头与经验传递，上工序波动全部传导 | `semisteel_transfer` 交接契约（M14）：上工序终点 = 下工序入炉条件，带置信与留痕 |
| S3 | **提温剂无系统求解** | 半钢温度不足时的提温剂方案靠经验 | reheating_agent_solver（M15），与冷却剂同框架 |
| S4 | **双厂复制靠人肉** | 攀钢/建龙参数口径不同；常数核对不到一半 | 通用引擎 + 厂级知识包（scope 分层），B 类参数入包 + lint 门禁 |

### 1.3 补充痛点（v0.2 自 workbuddy 方案 v1.1 吸收，已按边界裁剪）

| # | 痛点 | 机制 | VERO 处置 |
|---|---|---|---|
| P6 | **钒渣带铁损失** | 钒渣 TFe 高、半钢带渣入罐，直接制约收得率——提钒段核心损失点之一 | 复盘归因增加"带铁/带渣"归因通道；渣中 FeO 已在 ODE 状态内 |

## §2 智能体能做什么：业务参与清单

**参与的业务（三段 × 两工序 + 治理）：**

1. **冶炼前（开吹前 30~90 秒，一次性求解）**：开吹条件校验（硬拦截不合格）、配吃量计算、终点预测与目标轨迹、Si 敏感性 what-if、双口径对照、开吹指令单。
2. **冶炼中（8~12 分钟，10s 级滚动）**：状态估计、滚动终点预测（置信带）、偏差检测（对照开吹基准线）、枪位/供氧/补散状冷料建议（带剩余干预窗口，窗口一过自动失效）、Tc 越线告警。**影子期只记录不推送。**
3. **冶炼后（化验回来后）**：预测 vs 实绩自动对照、单炉归因（化验偏差 / k 常数失配 / 冷料实装不符 / 枪位执行偏离）、好炉次入判例库、批次偏差带统计、漂移告警与再标定建议。
4. **跨工序**：半钢交接契约（M14）+ 双厂知识包适配（M18）。
5. **知识治理**：参数变更双闸（漂移检测 + 专家签字）、黄金回归门禁、版本 diff 审批、判例库署名记账。

**不参与的业务（永久边界，越界即责任事故）**：写 DCS/PLC 任何形式、自动闭环（自动提枪/配加/调氧）、MES/ERP/QMS 改造、设备预测性维护、能碳管理、EHS 巡检、排产调度、钒渣下游焙烧工艺、大模型进入 10s 决策路径。

**三个数字岗位**（按"岗位说明书"三判据：有职责边界 / 有工作闭环 / 有汇报关系）：

| 数字岗位 | 职责边界 | 交付物 |
|---|---|---|
| 炉长推荐岗（冶炼中） | 只对一个炉次的三阶段推荐负责，不碰执行器 | 参数/操作建议卡 + 理由 + 置信度 + 采纳留痕 |
| 配料规划岗（冶炼前） | 对入炉条件与配料/提温剂方案负责 | 帕累托方案集 + 成本/回硫/渣量双标注 + 解释卡 |
| 工艺分析师岗（冶炼后） | 对炉次归因与判例沉淀负责 | 归因报告（三通道误差分解）+ 知识包修订建议单 |

**LLM 在体系中的位置**：理解（炉况语言化、异常归因）、编排（选工具、触发审批）、解释（把 σ 和 Tc 翻成人话）、留痕（推理链落 AdviceLog）——**零数值计算权，不编造常数，不绕过 ModeController**。

### 3.2 四条核心工作流

**W1 开吹前**（30~90 秒，一次性）：
化验单（时滞 3~15min，须标时龄）+ 铁水条件 → 开吹校验 F1.1（不合格硬拦截）→ 配吃计算 F1.2（A 总量 × B 分配）→ 终点预测 F1.3（本炉目标轨迹 = 中段比对基准线）→ 三要素证据卡 → 指令单（时间戳 + 规则版本）→ **炉长确认，留痕**。

**W2 吹炼中**（10s 级五步闭环，影子先行）：
采集（枪位/氧流 1s + 副枪 TSC/TSO 离散点 + 烟气 CO/CO₂ 1~5s + 称量斗实绩）→ 状态估计（ODE 递推 + KF 同化；无观测时纯外推并显式标注"外推中、置信下降"）→ 滚动终点预测（σ 来自 KF 协方差）→ 偏差检测（vs W1 基准线，红黄绿）→ 建议卡（同屏 ≤2 条，带窗口倒计时；块状冷料不给事中建议）→ 采纳/否决留痕。**降级链**：缺副枪→外推标注；无烟气→软测量兜底；断链→先验+confidence 降级（非静默）。

**W3 炉后复盘**（化验后 30min~数小时）：
实绩回流 → 预测 vs 实绩偏差带（分炉长/班次/Si 档）→ 归因四分法 → 达标炉次入判例库 → 漂移趋势告警 → 参数修订建议单。**修订不自动生效**，进 W4。

**W4 参数治理**（天/周级）：
知识包版本 diff → 双闸（漂移检测自动触发 + 专家委员会签字）→ 黄金回归 75/75 门禁 → 新版本生效，全程可回放可回滚。**认知可以概率化，执行必须受约束；任务执行与能力更新分离管理。**

## §4 本体构建（TBox 设计）

### 4.0 谱系锚点（v0.2，随 workbuddy A1 采纳）

本文类/关系**声明与 CROS（Cao et al. 2022, Computers in Industry）概念体系对齐**：CROS 复用 MASON/MSDL/SOSA-SSN/UFO 谱系——Material/Process 对应其资源与过程层，Observation/Sensor/Measurement 对应 SOSA-SSN，Constraint 为信息实体（不作顶层类）。顶层二选一原则采纳（随 CROS 或 IOF Core，不可混用）；VERO 现阶段**不引入 OWL 依赖**，以注释级映射防返工，OWL 形式化触发条件见 §4.6。

### 4.1 类层次（TBox）

```
vero:Thing
├── vero:Material                      # 物料（CROS 谱系对齐）
│   ├── vero:HotMetal                  # 铁水（C/Si/V/Ti/P/S/Mn/Cr/温度/重量）
│   ├── vero:SemiSteel                 # 半钢（残 V/残 C/温度；[Si]≤0.02% 文献口径见 §4.3）
│   ├── vero:Coolant                   # 冷却剂（块状=天车路径 / 散状=称量斗路径）
│   │   ├── vero:VRichSlagBall         # 钒渣铁
│   │   ├── vero:IronScale             # 氧化铁皮
│   │   ├── vero:Pellet                # 球团
│   │   └── vero:IronOre               # 块矿
│   └── vero:Slag                      # 钒渣（粗渣=装车样口径 / 精渣口径）
│       └─ Role 模式：钒渣可扮演「冷却剂」角色（v0.2 采纳 workbuddy）——同一 Material
│          节点经 playsRole 关联 Coolant 语境，避免双节点口径分裂
├── vero:Process                       # 过程（precedes 链：高炉→提钒→半钢炼钢→精炼→连铸；
│   │                                  #  仅提钒/半钢为建模域，其余为链上锚点不展开）
│   ├── vero:VanadiumExtractionBlow    # 提钒吹炼（8~12min，10s 级）
│   ├── vero:DecarburizationBlow       # 半钢脱碳吹炼
│   └── vero:SemiSteelTransfer         # 半钢交接（M14 契约）
├── vero:Device                        # 设备（v0.2 采纳）：氧枪/顶底复吹、底吹元件、挡渣装置、
│   │                                  #  称量斗/天车（加料路径的设备锚点）
│   └── participatesIn → Process       # 设备参与工序；枪位/氧量观测挂设备而非炉次
├── vero:Heat                          # 炉次（核心 ABox 节点：编号/时刻/班组/炉座）
├── vero:KnowledgeElement              # 知识元素
│   ├── vero:Parameter                 # 参数（四维：value/unit/source/status）
│   │                                  #  归入 Quality/Measurement 语境（挂测量主体与时点）
│   ├── vero:Rule                      # 规则/公式（四大平衡式、查表档位——离散档位勿拟合连续式）
│   ├── vero:Constraint                # 工艺窗口约束（v0.2 升格一等节点；数值窗口 P2 可选
│   │                                  #  SHACL shape 承载；若 EU 概念："提钒保碳窗口/化渣/泄爆"）
│   ├── vero:Conflict                  # 口径冲突（CF-001~007）
│   ├── vero:Evidence                  # 证据（黄金用例/回放记录/Excel 单元格溯源）
│   └── vero:Judgment                  # 判例（好炉次，带署名）
├── vero:Energy                        # 能源（v0.2 采纳）：煤气/电/提温剂热值——半钢段
│   │                                  #  提温剂求解（M15）的语义挂点
├── vero:Observation                   # 观测（v0.2 采纳，SOSA-SSN 口径）：Sensor(红外/副枪/
│   │                                  #  烟气/称量) → Observation → Measurement；blow 会话
│   │                                  #  三路融合即此类的运行时实例（含 data_age 属性）
├── vero:SteelTarget                   # 钢种/目标（v0.2 采纳）：半钢终点目标（温度/残钒上限/
│   │                                  #  保碳下限）、[Si]≤0.02% 窄窗口——客户必交清单第 4 项的本体化
├── vero:Defect                        # 缺陷（预留类，炼钢段）：causesDefect 因果链 P2+ 再启用
├── vero:Advice                        # 建议（requires_human_confirm=true，control_write=forbidden）
└── vero:Actor                         # 角色（炉长/一助手/二助手/工艺工程师/专家委员会）
```

### 4.2 关系（对象属性）

| 属性 | 定义域 → 值域 | 语义与实例 |
|---|---|---|
| `consumes / produces` | Heat ↔ Material | 一炉次消耗铁水、产出半钢+钒渣 |
| `hasByproduct` | Process → Material | 提钒工序的副产品=钒渣（v0.2 采纳；产出主品=半钢） |
| `precedes` | Process → Process | 工序先后链：高炉→提钒→半钢炼钢→精炼→连铸（链上节点仅锚定，不建模） |
| `participatesIn` | Device → Process | 氧枪/底吹元件参与吹炼工序（v0.2 采纳） |
| `playsRole` | Material → Coolant 语境 | 钒渣兼冷却剂的角色模式（v0.2 采纳） |
| `hasConstraint` | Process → Constraint | 工艺窗口约束关联工序；数值窗口 P2 可选 SHACL shape（v0.2 采纳） |
| `transfersTo` | Heat(提钒) → Heat(半钢) | **跨工序交接契约**：上工序终点即下工序入炉条件（S2 痛点的本体表达） |
| `governedBy` | Parameter → Rule | 参数由哪条规则/公式治理（如 dh_v 由 CF-001 冲突双方共同主张） |
| `conflictsWith` | Parameter ↔ Parameter | CF-001：`(dh_v, 2777, source=专家A热量!E18)` conflictsWith `(dh_v, 15000, source=MODEL_ALGORITHM.md)`，归属同一 Conflict 节点 |
| `evidencedBy` | Parameter/Rule → Evidence | 任何数值可溯源到黄金用例/回放/Excel 单元格 |
| `precedentOf` | Judgment → Heat | 判例对相似炉次的支撑（相似度 = Si/V 距离） |
| `adoptedBy` | Advice → Actor | 每条建议的采纳/否决签名（采纳记账） |
| `supersedes` | Rule/Version → Rule/Version | 参数版本链，可回滚 |
| `causesDefect` | 状态/约束 → Defect | 预留边（化渣困难→缺陷等，炼钢段 P2+ 启用） |
| `executedBy` |（否定性约束）| Advice **没有** executedBy 到执行器的边——控制写入路径在本体层面就不存在 |

### 4.3 数据属性（关键）

- Parameter 四维：`value / unit / source / status`（status ∈ draft|approved|deprecated——对应知识包批准流）
- `confidence`（σ，来自 KF 协方差，禁硬编码线性式）、`data_age`（化验/观测时滞显式化，防"拿滞后数据冒充实时"）
- Heat：`heat_id / furnace_id / shift / timestamp / is_degraded`（降级炉次禁止进 KPI 合同轨）

### 4.4 与现有资产的映射（本体 = 知识包的语义视图，不是第二真相源）

| 现有资产 | 本体表达 |
|---|---|
| `knowledge/packs/*/base.yaml` parameters 树 | Parameter/Rule 节点 + governedBy 边（YAML 是物理载体，本体是逻辑视图） |
| `known_conflicts`（CF-001~007） | Conflict 节点 + conflictsWith 双 Parameter 边 |
| `pack_discrepancies()` 包/代码一致性校验 | Parameter 节点 ↔ 代码常数的 evidencedBy 一致性断言 |
| 判例库（好炉次 + 署名） | Judgment 节点 + precedentOf 边 |
| `AdviceLog` 表 | Advice ABox + adoptedBy 边（天然入图） |
| `DATA_INTERFACE_SPEC v0.2` 字段字典 | Heat/Material 的数据属性（单位与口径即语义） |
| `semisteel_transfer` 契约（M14） | transfersTo 边上的约束节点 |

### 4.6 实施三步（渐进演进，不另起工程）——与 workbuddy 七步的映射

workbuddy 七步（定范围→复用谱系→专家+文档抽取→OWL 形式化/SWRL+SHACL→OBDA 实例化→接智能体→持续演进）与本方案三步的对应：其 1~3 步 ≈ 本方案三步的全部（本方案以"知识包语义视图"形态轻量落地，跳过 OWL 中间态直接服务运行系统）；其 4~5 步（OWL/SWRL 形式化、OBDA 实例化）**列为 P3+，触发条件 = 标准卡位立项**（开源 vero.knowledge-pack schema + 行业基线包时才值得付形式化成本）；其中 **SHACL 窗口约束**成本最低、收益直接（工艺窗口变机读校验），**单列 P2 可选项**：

1. **schema v1.1.1（0.5 人日）**：YAML 参数节点补齐四维注释——现有包已有 value/unit/source 大半，补 `status` 与 `confidence`；`plant_a_pack.py` 校验器同步。
2. **Conflict 显性化（1 人日）**：CF-001 双 Parameter 节点 + 证据链入 industry/plant 包，`list_conflicts` 输出与本体视图对齐（本次修复后该 API 已具备三层聚合能力）。
3. **P2：Judgment/Evidence 入图 + transfersTo 契约（随半钢段 P2）**：判例库、黄金用例、半钢交接契约以图结构建模；向量检索待百炉数据后启动；**可选加练 SHACL 窗口约束**（Tc/温度窗/余钒/[Si] 先行）。

## §5 附一：部署位置决策表（文章 5 五问法落地）

| 模块 | ① 实时性 | ② 断网容忍 | ③ 数据合规 | ④ 算力 | ⑤ 谁有权向执行器发指令 | 部署层 |
|---|---|---|---|---|---|---|
| 开吹前配料/品位预测 | 30~90s 窗口 | 分钟级可容忍 | 化验数据不出厂 | CPU 即可 | **无人（建议单）** | 厂内云/内网服务器 |
| 冶炼中状态估计与建议 | 1~10s 刷新 | 中断 30s→显式降级外推 | 全数据厂内 | 单核 ODE 富余 | **无人（建议卡）** | 厂内边缘服务器（近实时 20~100ms 级能力富余） |
| LLM 理解/编排/解释 | 秒级 | 可降级为模板文案 | 生产路径内网/本地模型 | 视模型规模 | 零数值权 | 厂内云（离线推理） |
| 复盘归因/RLS 标定 | 小时级批处理 | 无要求 | 台账不出厂 | 批处理 | 无人（修订建议单） | 厂内云 |
| 安全联锁/急停 | 毫秒级 | **必须独立运行** | — | — | **PLC 独有，VERO 永不触碰** | PLC 硬件回路 |

> 第 ⑤ 问优先级最高——它决定了 VERO 的部署形态："可以建议到执行器面前，不可以越过执行器"。

## §6 附二：效益基线纪律（防"编数字"）

- 我方效益基线**只允许**来自：本厂历史炉次实绩（双方签字）、四大平衡引擎已验证输出、16 炉回放口径（真实数据本机复现）。
- 他人工业案例数字（矿石分选年增 2000 万、空压节能 7.7%、图纸审核 10 倍、数字孪生 CapEx −10~15% 等）**一律不得**进入本项目 KPI、效益测算或演示文档；对外引用须标"他人案例，非本项目基线"。
- 合同口径一律"基线 ±Δ + 对赌分档"（影子期免费联合测基线 → 达标转正 / 部分达标阶梯价 / 未达标无条件终止）。
