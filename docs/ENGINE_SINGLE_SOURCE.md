# 引擎单一真相源政策 (Engine Single Source of Truth)

> VERO（提钒冶炼智能体）· 工程化底座 · 180 天行动计划 D2
> 生效日期：**2026-09-27**　状态：**已生效**
> 关联文件：`backend/tests/golden_cases.json`、`backend/tests/test_engine_parity.py`

---

## 0. 一句话结论

**唯一计算权威 = Python 后端 `backend/app/tools/pangang_reference.py`。
HTML 演示页里的 JS 引擎自 2026-09-27 起单向冻结、自然死亡，不再迭代模型，Python 侧的新机理永不回移 JS。**

---

## 1. 背景与问题

- 前端 `VERO_MVP_v0.8.html`（及其后续版本）内联了一份从 Python 逐公式移植的 JS 引擎
  （`runModel(...)`，返回 `{fc, slg, steel, o2kg, tI, tS, surplus, pl, steel2, grade, balPct}`）。
- 该 JS 引擎与 Python 基准曾对齐 **11/11**，但这是**一次人工快照，不是机制**。
- 机理一旦在 Python 侧迭代（新的热平衡项、新的冷料口径、知识包参数下沉），
  JS 侧会**静默漂移**——演示页数字与服务端不一致，且无人察觉。

---

## 2. 冻结声明（JS 引擎）

| 项 | 内容 |
|---|---|
| 冻结对象 | `VERO_MVP_v*.html` 中第一段内联 `<script>` 内的攀钢四大平衡引擎（`runModel` 及其常量 `K`/`COOL`/`EP`） |
| 冻结日期 | **2026-09-27** |
| 冻结范围 | 全部**计算模型**：物料平衡、热量平衡、冷料边际响应、钒平衡、品位反算 |
| 冻结后允许 | **只修 bug**（崩溃、NaN、渲染错误、单位显示错误），且修复后数值必须与冻结基准一致 |
| 冻结后禁止 | ① 新增/修改模型机理 ② 调参 ③ 引入新知识包口径 ④ 与 Python 对齐式"追赶"改动 |

> 判定规则：一次 JS 改动若改变了 11 项黄金基准中任意一项的数值（相对误差 > 1e-4），
> 即视为**模型迭代**，一律拒绝。

---

## 3. 唯一计算权威（Python）

- **权威实现**：`backend/app/tools/pangang_reference.py`（`run_pangang_model`）
- **权威输出**：所有对外数值（API / MCP 工具 / 前端 / 报告）必须源自该模块或由其派生的服务层。
- **参数来源**：机理常数与厂级参数逐步下沉到 `knowledge/packs/**/base.yaml`，
  代码中的专家常数保留 Excel 单元格溯源注释作为 provenance。
- **Python 侧迭代**：允许且鼓励。迭代后按第 5 节处理基准文件。

---

## 4. 禁止回移（单向闸门）

```
Python 权威引擎  ──迭代──▶  新机理
                              │
                              ✗ 禁止回移
                              ▼
                        JS 演示页引擎（冻结）
```

- **任何**把 Python 新机理"同步"回 JS 的 PR，一律拒绝合并。
- 如需演示页展示新机理：走后端 API（React 前端）取数，**不复制公式**。
- 唯一例外：JS 引擎按第 7 节退役删除。

---

## 5. Parity 测试 = 红灯机制

**文件**：`backend/tests/golden_cases.json`（单一真相源）+ `backend/tests/test_engine_parity.py`

**运行**：

```bash
cd /Users/yanwenqing/Documents/VAgent
python -m pytest backend/tests/test_engine_parity.py -q -s
```

**机制**：

1. `golden_cases.json` 保存 11 项黄金基准（输入 `{W:80000, Si:.215, V:.284, T:1300, C:4.3, dhV:2777}`，
   容差**相对误差 1e-4**），附 `meta`（来源、冻结日期 2026-09-27）与 `mapping`（Python/JS 字段映射）。
2. 测试做三重校验：
   - ① Python 引擎 vs 黄金基准（**权威校验，必须全绿**）
   - ② JS 引擎（Node 子进程执行首段 `<script>`）vs 黄金基准
   - ③ JS vs Python 互比（漂移检测）
3. Node 不可用或演示页缺失时 **skip 而非 fail**（环境降级）；
   JS 一旦能跑，任何一项漂移即 **CI 失败**。

**漂移处置流程**：

| 漂移方 | 处置 |
|---|---|
| JS 漂移（Python 仍对） | **JS 有问题**：只修 bug 到回到基准；修不回则按第 7 节触发退役 |
| Python 漂移（JS 仍对基准） | 说明机理已迭代：必须**专家评审 → 修订 `golden_cases.json` 期望值 → 同步更新本文档与 `meta.frozen_date`**，**禁止**改代码迁就旧值 |
| 同时漂移 | 冻结 CI，人工仲裁 |

> 红线：`golden_cases.json` 的期望值**不得为了让测试通过而修改**。

## 7. React 前端跑通后的退役流程

**死亡触发条件**：React 前端跑通一次完整的后端计算闭环（即从 UI 输入 → 后端 API/MCP 工具 → 返回权威数值 → 渲染）。

**退役步骤**：

1. **触发确认**：React 前端完成一次闭环联调，留痕（炉次号 + 请求/响应 + 截图）到 PR。
2. **Parity 末次运行**：执行 `test_engine_parity.py`，记录最后一次 11/11 结果作为历史证据存档。
3. **冻结测试降级**：把 JS 相关用例标记为 `@pytest.mark.skip(reason="JS 引擎已退役")`，
   保留 `golden_cases.json` 与 Python 侧用例（继续守护权威引擎）。
4. **删除 JS 引擎**：移除 `VERO_MVP_v*.html` 第一段的 `runModel` 引擎脚本，页面改为调用后端 API；
   历史 HTML 版本作为快照归档，不再维护。
5. **文档更新**：本文档 §2 状态改为「已退役」，注明退役日期与替代入口。
6. **CI 校验**：CI 中增加一条检查——`frontend/` 与 `web/` 源码中不得出现攀钢平衡公式常量
   （`1.157` / `29177` / `0.42` 等特征常数），防止引擎复活。
